# 通知内容与规则

三条通知默认全部开启，可在管理台「通知设置」调整。每次运行重新读取开关、接收人和阈值，无需重启。SparkX Token 保存之前不会运行，也不会留下失败记录。

## 接收人与 @ 规则

| 通知 | 通知群 | 群内 @ | 私聊 |
|---|---|---|---|
| 08:30 日报 | 发送（默认） | 不 @ | 总负责人（默认） |
| 异常复盘 | 发送（默认） | 有问题店铺的对应运营（默认） | 广告负责人（默认）；对应运营只含其店铺（可选，默认关） |
| 实时监控 | 发送（默认） | 本次新提醒店铺的对应运营（默认） | 广告负责人（默认）；对应运营只含其店铺（可选，默认关） |

- 店铺还没有指定运营时照常发送：表格里标注「未映射运营」，群消息不 @ 任何人。
- 在「店铺与运营」为店铺指定运营后，这家店出现异常时，群消息顶部显示「对应运营：@某某」，只 @ 这次涉及的店铺的运营，其他运营不会被 @。
- 只 @ 仍在通知群里的成员。消息排队后若运营被更换或移出群，发送时不再 @ 此人，消息照常发出。
- 同一人既是广告负责人又是运营时，群里会被 @，同时收到广告负责人的私聊；不想重复可以关掉「私聊广告负责人」。

## 数据口径

- 一次运行一个 SparkX 会话：先 `get_user_authorized_context` 取得 Token 授权的店铺（Profile），去掉管理台里关闭监控的店铺，再对其余店铺做**一次多店查询**。多店查询的金额由 SparkX 统一折算为 USD（单店时为当地币种），卡片注明币种。
- 日期按美西（`America/Los_Angeles`）：08:30 北京时间对应美西前一天下午，日报取美西「昨天」的前一天，即最近一个已结束的完整日。
- 每个比率都由加总后的基础指标重新计算（ACOS=花费/广告销售额，CVR=广告订单/点击，PPC=花费/点击，ROAS=广告销售额/花费，TACOS=广告花费/店铺总销售额），不对比率求平均。
- TACOS 只统计同时有广告行和店铺总销售行的店铺，保证分子分母口径一致。店铺总销售额来自 `factEntity: asin` 的 `TotalSalesAmount`、`OrderCount`；这项查询失败时日报照常发送，总销售额与 TACOS 显示「—」并注明。
- SparkX 没有返回的店铺或指标显示「—」或列为「SparkX 无记录」，从不写成 0。前一日有数据的店铺数与当日不同时，卡片注明环比口径。

## 08:30 广告日报

结构（参照 SparkX 代理的日报格式）：

1. 统计范围：数据日、环比日、监控店铺数、有数据和有花费的店铺数、金额单位。
2. **全公司核心指标**：店铺总销售额、总订单量、广告花费、广告销售额、广告订单、ACOS、TACOS、CVR、PPC、ROAS，各有当日、前一日、环比（比率类为百分点差）。
3. **站点汇总**：站点 / 币种 / 店铺数 / 有数据 / 花费 / 销售额 / 销量 / 订单 / ACOS / ROAS / 花费环比 / 销售额环比，多个站点时加合计行。
4. **有花费店铺明细**：店铺 / 运营 / 花费 / 销售额 / 销量 / 订单 / ACOS / TACOS / 花费日环比；当日无花费与 SparkX 无记录的店铺另列名单。
5. **N 点须知**：DeepSeek 依据服务端整理的事实撰写（站点缺数据、花费集中、ACOS 分化、零出单、效率最好的店铺等）；未配置、失败或未通过数字核对时使用规则文字。

接收人：通知群 + 总负责人私聊（日报不 @ 运营）。

## 08:30 广告异常复盘（近 7 日对比前 7 日，campaign 级）

| 类型 | 判定（金额为 USD） | 建议 CPC |
|---|---|---|
| 全店零曝光 | 两周没有任何曝光，且仍有开启的 campaign（`get_entity_metadata` 计数） | — |
| ① 高花费零出单 | 近 7 日花费 ≥ $50、点击 ≥ 10、订单 = 0 | 当前 CPC × 70%（先降 30% 并排查搜索词） |
| ② ACOS 明显恶化（高花费低转化） | 近 7 日花费 ≥ $50，ACOS ≥ 前 7 日 × 1.5 且至少高 15 个百分点 | 当前 CPC × 前 7 日 ACOS ÷ 近 7 日 ACOS |
| ③ 加预算后销售反而下滑 | 花费 ≥ $50 且较前 7 日 ≥ +30%，销售 ≤ −20%（或零出单但前 7 日有销售） | 收回新增预算 |
| ④ 异常停摆 | 开启状态，前 7 日花费 ≥ $50，近 7 日无曝光 | 查预算、断货、限流 |
| ⑤ 低花费高转化（机会） | 近 7 日花费 < $100、订单 ≥ 3、ACOS ≤ 20% | 可加预算或出价放量（不计入异常数） |

卡片分为：一、最严重；二、异常店铺总览（店铺 / 运营 / 近 7 日花费 / ACOS 近 7 日 / 前 7 日 / 异常数 / 主要问题）；三、按问题类型看具体 campaign；四、建议动作（DeepSeek 撰写，每条对应一家店铺，只能引用已算好的 CPC 建议）。两周零数据但没有开启 campaign 的店铺单列，不计为异常。

接收人：通知群（@ 有问题店铺的对应运营）+ 广告负责人私聊，均为全部店铺。可选再私聊每位运营只含其店铺的部分（同一人既是负责人又是运营时只收一份私聊完整版）。

## 每小时实时监控

每小时读取美西当日截至目前的 campaign 数据（SparkX 当日累计，订单归因会延迟数小时），只看开启状态的活动：

| 类型 | 默认判定（管理台可改） |
|---|---|
| 高花费无转化 | 花费 ≥ $30 且订单 = 0 |
| 高花费低转化 | 花费 ≥ $30，有订单但 ACOS ≥ 60% 或 CVR < 5% |
| 低花费无转化 | $10 ≤ 花费 < $30，点击 ≥ 15，订单 = 0 |
| 低花费高转化 | 花费 < $30，订单 ≥ 2 且 ACOS ≤ 20%（放量机会） |

- 同一活动同一类型每个美西自然日只提醒一次；活动升级到另一类型（如低花费无转化 → 高花费无转化）时再提醒。
- 只在管理台设定的北京时间段内运行（默认 09:00–24:00）；排队超过 50 分钟仍未发出的提醒作废，不补发。
- 接收人：通知群（@ 本次新提醒店铺的对应运营）+ 广告负责人私聊；可选再私聊对应运营（只含其店铺）。

## 发送与核对

- 卡片在排队时冻结，同一接收人、同一天（实时监控为同一小时）只排一次。
- 日报和复盘只在北京时间 08:30–12:00 发送，生成窗口 08:30–10:00；SparkX 失败时每 10 分钟重试，最多 6 次。
- 每次发送前重新核对：通知仍开启、该发送对象仍开启、仍在发送时段、负责人未更换（按绑定代次）、运营仍对应这些店铺且仍在通知群。不满足就保留记录不发送。
- 发送前先写入投递意图；之后若出现超时等不确定结果，标记为「可能已提交」，不自动重发。
- 旧版本遗留在发送队列里的消息不会发送，保留为「已跳过」。
