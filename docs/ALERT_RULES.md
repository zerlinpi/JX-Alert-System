# 异常规则入口

当前完整规则见 **[JX-Alert-System：提醒规则与系统运行逻辑](SYSTEM_RULES_AND_LOGIC.md)**。

其中：

- [初筛规则](SYSTEM_RULES_AND_LOGIC.md#6-初筛规则)：15%初筛、基础样本与候选记录。
- [最终通知门槛](SYSTEM_RULES_AND_LOGIC.md#7-最终业务提醒门槛)：实际影响、样本、两日期确认、严重例外及三个发送出口。
- [健康与数据质量](SYSTEM_RULES_AND_LOGIC.md#8-店铺状态绩效与数据质量)：仅观测模式、源时间、动态平台标准及授权状态。
- [生命周期](SYSTEM_RULES_AND_LOGIC.md#9-异常生命周期与去重)：NEW/ONGOING/ESCALATED/RECOVERED和48小时升级。
- [时间口径](SYSTEM_RULES_AND_LOGIC.md#3-四种时间与报表日期)：保留领星原始时间，明确偏移优先，无偏移不套服务器时区。
- [精简门槛表](ALERT_MATERIALITY.md)：运营提醒基准速查。

旧版本文中的下列描述已撤回：

| 旧描述 | 当前行为 |
| --- | --- |
| 缺任一店时区就全局停采 | 逐店处理；可启用未知时区的保守历史采集 |
| 完整采集后未返回字段可补0 | 仍须有明确源事实；接口空记录、真实零、失败与未采集分开 |
| 绩效和业绩通知尚未自动采集 | 已自动观测归档，业务健康通知继续受仅观测开关保护 |
| 无转化必须此前有订单 | 初筛不要求此前有订单；最终还要成熟、样本及实际影响等证据 |
| NEW必发、RECOVERED必发 | 受门槛、模式、开关、路由及相应恢复条件限制 |
| 两天升级等于第三个完整报表日 | 升级按first_seen起48小时墙钟；普通实质异常的两报表日确认是另一机制 |
| 高花费或指标增长就是异常 | 正向增长不通知；单纯高花费从不直接通知 |

当前线上开关值与默认值的区别，以总文档的运行快照及实际运行配置为准；不能据初筛记录数量推断飞书已送达数量。
