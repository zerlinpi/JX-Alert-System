# 异常规则与数据口径

## 日期边界
所有业务日期以店铺 marketplace 时区为准。日报日期 D 为该店铺本地前一完整自然日；基准期为 D-1 至 D-7 共七个完整自然日。自动调度从 `data/store-timezones.json` 读取每个 sid 的 IANA 时区。缺少任一活跃店铺的时区配置时，调度 fail closed，不猜测日期。

## 销量与销售额
默认按店铺、MSKU 和 ASIN 独立计算订单量、销量和销售额。变化率 = (D 指标 - 前七日均值) / 前七日均值，默认绝对阈值 15%。基准均值低于 `ALERT_MIN_ORDERS_BASELINE` 或为 0 时不触发百分比规则。
领星销量接口的 type=1/2/3 分别映射销售额、销量、订单量。数据按 ASIN 和 MSKU 分别采集，店铺汇总仅从 ASIN 粒度汇总，避免重复计数。

## 完整性与缺失值
每个 store/date/dimension 写入 `data_coverage` 完整性记录。只有某维度 D-7 至 D 八天全部标记 COMPLETE，才允许将该维度未返回的指标解释为 0。缺少 coverage、分页中断、响应结构异常时，不把缺失数据当成 0，也不恢复已有异常。

## 广告活动
已接入 SP/SB/SD 活动级日报和活动基础资料。SP/SD 活动报表按 `next_token` 游标分页，SB 活动报表按 `offset/length` 分页。Campaign 级数据按 store + campaign type + campaign ID 保存。
- 高花费：当日花费达到七日均值的 `ALERT_HIGH_SPEND_RATIO` 倍，且达到最低花费门槛。
- 无转化：当日花费、点击达到配置门槛，订单为 0，且历史七日订单均值大于 0。
- 低花费无转化：启用中的活动花费低于七日均值的配置比例且当日订单为 0，作为低优先级观察。
- 预算消耗：仅对 `budget_type=daily` 的活动，提醒花费达到日预算比例；不等同于平台超预算违规。
- 超预算事件：活动基础资料中的 `lastOverBudgetAt` 日期等于报告日时触发。

SP/SD 商品广告日报已接入，可按 ad_id 保存商品级花费、订单、销售额、销量、点击和曝光，并映射到 MSKU/ASIN。当前未确认 SB 商品级广告报表接口，不将 SB 活动花费或订单分摊到商品。

广告销售额/订单属于平台归因口径，不等同于领星店铺总销售额；不同广告类型或归因窗口不可直接与店铺销售额相加比较。

## 店铺状态
店铺列表状态码不为 1 时创建 `store_status_not_normal` 事件。状态码按领星官方「查询亚马逊店铺列表」接口枚举解释：
- 0：停止同步（P2）
- 1：正常
- 2：授权异常（P1）
- 3：欠费停服（P1）
其他未定义状态码按未知状态处理（P2），不猜测具体原因。状态恢复为 1 后自动恢复对应事件。

注意：这是**领星 ERP 授权/同步状态**，不等于 Amazon Seller Central 的 Account Health、政策违规或绩效通知。账户健康评分、绩效事件和业绩通知仍需接入其独立且已核实的领星接口，不能用店铺同步状态代替。官方字段枚举见：[查询亚马逊店铺列表](https://apidoc.lingxing.com/new/api-docs/BasicData/SellerLists/)。

## 尚未接入的数据源
- 账户健康/店铺绩效列表、绩效详情、业绩通知列表接口的准确请求路径、字段和响应结构尚未核对。
- 产品表现异步报告 `reportType=2` 需要 `reportOptions` 嵌套对象的签名 canonicalizer；当前客户端拒绝猜测嵌套对象签名。
- SB 商品级广告报表接口尚未核实。

## 通知生命周期与持续升级
- NEW：首次发现，立即进入通知队列。
- ONGOING：持续存在，只更新记录，不重复刷屏。
- ESCALATED：规则严重程度上升，或异常持续达到升级天数，通知一次。
- RECOVERED：完整数据证明指标恢复，发送恢复通知。
- CLOSED：人工确认关闭（当前保留状态定义，尚未开放 MCP 写操作）。

默认 `ALERT_ESCALATE_AFTER_DAYS=2`：首次发现当天为第 1 天，连续到第 3 个完整日评估仍异常时触发一次升级。升级时 P3→P2、P2→P1、P1 保持 P1；升级后的严重级别在恢复前不会自动降回。可通过配置调整天数。恢复状态只能在完整采集并完成同一实体/规则的检测后产生。数据采集失败或分页不完整时，不允许自动恢复。
