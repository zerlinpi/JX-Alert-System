# 飞书群内/私聊店铺问答与 Excel 归档

在已有自建应用和“独立站交接群”内增加长连接问答。群成员明确 @机器人并给店铺全名、品牌或名称片段，机器人在原消息话题内回复数据表与简短中文分析。支持大小写、全半角与常见分隔符差异。同品牌跨站点先列店铺名及站点，补充“川页美国”即可，不要求编号，不猜店铺。仅指定日报群可使用，不读取其他群的消息。

也支持已授权用户私聊机器人，无须@，回复留在原私人会话。通知群可在运营台「通知群设置」替换，动态生效；机器人只读问答不会授予采集或数据修改权限。操作与新增单聊权限见[通知群替换与机器人私聊](FEISHU_GROUP_AND_PRIVATE_CHAT.md)。

可以直接问“现在有哪些店铺数据”或“所有店铺绩效和违规情况”，无需先指定店铺。默认排除采集/通知均关闭的店铺，明确问已关闭/历史店铺时可查看。只问绩效不附广告表，空SB/SD默认省略。发送“帮我更新Geteen美国的数据”等刷新要求会提示使用后台同步，不会新增采集任务。详见[早间快报与自然提问](MORNING_BRIEF_AND_QUESTIONS.md)。

回复按问题选择已保存的经营、广告、七项广告指标和绩效观测，省略空白字段与无关指标。经营看板接入后，日报使用销量、净销售额、平台收入、毛利润、毛利率、广告费占比、退款率四列表格；旧销售额不冒充净销售额。金额币种、比较日期、成熟归因日与相关数据缺口仍保留。表格由数据库生成，分析由DeepSeek基于本次冻结数据生成；模型没有广告修改、执行命令或任意工具能力。活动分析使用当前花费前10个样本，不能称已完成全部活动巡检。只读预估与可用数据边界见[经营日报与只读分析](BUSINESS_DAILY_AND_READONLY_ANALYSIS.md)。

问答进程独立于Chat MCP。消息事件先持久化，模型请求在独立工作线程执行；原MCP地址、OAuth及已安装连接保持兼容。每个消息ID只入队一次，投递重试复用UUID；恢复不会重复累加花费。输入最多1200字、模型回复最多6000字，同一成员每分钟最多3个新问题，队列有上限。等待超过30分钟的旧问题不延迟刷群。未配置或模型暂不可用时只返回已有数据与不可用提示，不冒充分析完成。

## 一、私下保存 DeepSeek API Key

在自己的服务器终端执行，不要将密钥粘贴进聊天或命令参数：

```bash
cd /opt/jx-alert-system
sudo docker compose -p jx-alert exec app python /app/scripts/setup_deepseek.py
```

脚本隐藏输入并二次确认，保存到 `/app/data/secrets/deepseek.json`（宿主机 `data/secrets/deepseek.json`），权限0600，拒绝覆盖已有文件。不会修改`.env`。默认模型 `deepseek-flash`，可在运行配置中选 `deepseek-v4-pro`；只使用官方HTTPS地址。此步骤不发起计费请求，真实请求仍需账户余额和可用额度。

## 二、飞书应用开通接收

**保存长连接模式之前，必须已有在线客户端。** 完成第一节私有密钥初始化后，先执行第三节命令启动机器人，再保存下列订阅方式。未完成订阅发布前，不声称群内问答已验收。

1. 在飞书开放平台进入现有自建应用，确认机器人能力已启用且已经加入“独立站交接群”。
2. 在“权限管理”启用群内 @消息读取权限 `im:message.group_at_msg:readonly`、私聊读取`im:message.p2p_msg:readonly`；发送沿用 `im:message:send_as_bot`，成员核实使用`im:chat.members:read`。不需要申请读取群全部消息。
3. 左侧进入“事件与回调”，打开顶部“事件配置”页。在“订阅方式”旁点击“编辑”，选择“使用长连接接收事件”，点击“保存”。不填写公网Webhook或回调URL。
4. 在同页下方“已添加事件”区域点击“添加事件”，搜索“接收消息”，勾选 **接收消息 v2.0**（标识 `im.message.receive_v1`），确认添加。显示名的v2.0和标识中的_v1是该事件的正常对应关系。
5. 左侧进入“版本管理与发布”，创建新版本，填写版本号及“启用群内机器人问答”等更新说明，保存并提交发布；按企业要求完成审批。只保存权限和事件配置尚未生效。
6. 发布后在“独立站交接群”从@列表选择该机器人，发送“5174店铺的广告和绩效情况，只列出异常和待确认项”。手打机器人名称不等于真实@。

若找不到“添加事件”，先确认当前打开的是“事件配置”页，并已保存订阅方式；事件不在“权限管理”页面添加。

机器人启动时用官方机器人信息接口核实自身Open ID，不需要把机器人、管理员或运营ID硬填到问答代码中。白名单群沿用 `feishu_daily_report_chat_id` 和现有路由文件。运营/管理员映射仍服务原有定向告警，不会被问答改写。

## 三、启用独立机器人

代码已通过测试并同步服务器、私有密钥初始化完成后执行，以便在飞书保存长连接模式：

```bash
sudo docker compose -p jx-alert exec -T app python /app/scripts/activate_feishu_bot.py
sudo docker compose -p jx-alert --profile bot build bot
sudo docker compose -p jx-alert --profile bot up -d --no-deps bot
```

只构建/启动新增bot服务，不重建数据库、应用、MCP或调度器。激活脚本为原运行配置创建私有备份，再启用机器人与Excel归档。机器人可独立重启，Chat MCP不依赖DeepSeek。

群内示例：`@机器人 5174 店铺的广告和绩效情况，列出需要关注的内容`。正常情况下，话题内会出现真实数据卡和分析卡。新鲜度未确认、授权失败、缺少基线、分母为零和样本不足均保留状态。源时区未确认时只展示健康观测，不新增或恢复健康风险业务告警。

使用MCP仍可说：“查询全部店铺绩效快报”或“检查5174的广告指标”。原来的日报与异常通知不受群问答开关影响。

普通问答的目标日尚无任何采集证据时，可展示近七日最近同一天完整采集的日报，并明确列出查询目标日与实际展示日。不会把历史数值称为当日；明确指定日期、最新采集失败或授权异常时，不静默改用其他日期。接口成功但返回空记录与未采集分别展示，空记录不自动变成零花费。

机器人仅提供只读问答和分析。即使店铺负责人或管理员发送 `@机器人 实时采集 Geteen 美国`，也只收到后台同步的操作提示，不会创建采集任务，不会修改广告、预算、库存或任何源数据。人工刷新请在运营台使用单店或全部店铺同步；原有定时采集与受授权ChatGPT MCP采集独立运行，仍受店铺范围、采集开关、授权和报表日期约束。

旧版本已有机器人采集回执的会话，仍可用 `@机器人 Geteen美国采集进度` 只读查询其历史任务。状态查询复验权限，私聊回执绑定原发送者；没有历史回执时提示到后台查看，不把MCP或后台任务冒充本群任务。普通问答继续读取已有数据。

## 异常通知与调用成本

通知基准、门槛及上线/回滚方式见[异常通知基准](ALERT_MATERIALITY.md)。七项指标和完整数据表由服务端继续生成，模型仅接收去除重复指纹、重复日期数组和内部展示元数据后的冻结证据。样本范围、实际日期、币种、数据缺口、活动状态及全部七项指标保留。

同会话、同发送者、相同问题和相同冻结数据的成功分析最多复用原始生成时间起10分钟。数据、质量状态、日期、模型或提示词改变即失效；失败结果不缓存。缓存不影响真实采集。模型输出上限1536 tokens、最多6条且500字内；超限或不完整响应仍拒绝发布。用量仅保存官方返回的数字计数，不保存请求头或密钥。原MCP不等待DeepSeek。

## 四、Excel 保存位置与实时含义

宿主机目录为 `/opt/jx-alert-system/data/excel/YYYY/MM/DD/`，容器内为 `/app/data/excel/`。每次采集步骤成功提交后更新对应店铺、报表日的Excel；部分采集失败也保留已成功提交的数据。

普通报表保留原有七张工作表，增加原始事实、采集覆盖、七项广告指标、健康快报和归档信息。“最新”文件原子替换，内容版本文件保留。真实零值与缺失空白分开，长ID按文本存储，外部名称不能变成Excel公式；不导出密钥、客户身份信息或任意原始响应。

SP独立采集版本保存在采集UTC日的 `YYYY/MM/DD/SP/`：日报、小时、广告商品、投放和对账分别列出，保留run_id和差异，不把多个版本相加。原始JSON和数据库仍保留。Excel失败进入独立重试队列，不靠重新调用领星来弥补文件写入失败。

这里的实时是“采集成功后归档”，不是宣称领星接口本身每秒更新。文件内标明报表日期和采集时间。可用SFTP/WinSCP登录现有服务器后下载该目录，不将含业务数据的文件夹公开到互联网。

此外，每天北京时间23:30将服务器已有全部业务历史保存为一套全维度Excel快照，目录 `/opt/jx-alert-system/data/excel/daily/YYYY/MM/DD/`。这与按报表分区更新的Excel同时保留；维度、手动导出和校验方法见[每日完整Excel](DAILY_EXCEL_ARCHIVE.md)。

## 验证与停用

实际模型联调必须在私钥初始化后执行。群内实测同时核对问题消息ID、持久化任务、outbox及飞书返回的message_id；“已入队”不代表已送达。配置关闭或外部调用失败不影响MCP读取和现有定时任务。

停用新增问答：`sudo docker compose -p jx-alert --profile bot stop bot`。不删除数据目录或Docker卷；保留已归档Excel和历史业务事实。
