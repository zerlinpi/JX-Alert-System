# 负责人经营日报

参考 [Grafana 表格](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/table/) 的概览与明细分层，以及 [飞书原生表格](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/table) 的组件限制：先发同币种汇总，再分页发店铺明细。用真实卡片生成代码离线预览虚构示例，不发飞书：

```sh
PYTHONPATH=src python scripts/preview_owner_daily.py
```

| 指标 | 口径 |
| --- | --- |
| 广告花费 | 领星[产品表现](https://apidoc.lingxing.com/new/api-docs/Statistics/AsinListNew/)的 `spend`。使用已验证的完整 ASIN 分区，包含源端支持的 SP、SB、SBV、SD 及共享分摊；不再加广告活动报表，避免重复。不是广告账单对账总额。 |
| 净销售额 | 同日期同店铺产品表现 `net_amount`；明确为净额，非结算收入。 |
| 件数退货率 | 同一观察窗口内的 `return_goods_count / volume`：分子为实际退货当日的件数（`purchase_status=0`），分母为当日下单销量。按同一完整覆盖集合汇总分子分母后相除，不平均店铺百分比；非原订单批次最终退货率。零分母不报 0%；跨期退货可超过 100%。 |
| 销售退款额 | 领星[店铺利润报表](https://apidoc.lingxing.com/new/api-docs/Finance/bdSeller/)的 `totalSalesRefunds`，按结算日和已发放状态取扣款绝对值。不是实时退款承诺，不含其他费用退款，不从净额里再扣一次。 |

## 日期和缺口

卡片写实际的店铺统计日和生成时刻（不是供应端更新时间），不用北京时间的「今日」替换。未结束的店铺日期只能读该日期、距生成时不超过 90 分钟的已存分区，并标成暂估；不拿昨日数据顶替，也不启动额外采集。已结束日期只接受收盘后的同日分区。以同一统计日、同一币种出汇总；不做跨币种加总、不把空接口当成零，也不把部分覆盖叫全量。

现有早报仍按已结束的店铺当地统计日及北京时间 09:00 发送规则工作。试点开关 `FEISHU_OWNER_DAILY_REPORT_ENABLED` 默认关闭，只在验证数据后由部署人员在隔离环境启用。开启后在现有早报中把负责人汇总和分店铺卡置于前面，替代单店经营卡，不替代店铺健康或实质广告异常；不另开自动推送。没有同日报表或全范围无可核验指标时保留既有日报行为，不虚构负责人数据。要上线「今天截至某时」，仍需验证当前日产品表现/退款数据可用性，商定截止和投递时刻，再安排独立同日取数与投递，不要把早报日期改名。

## 收件范围及回滚

只沿用现有已确认的飞书应用通知群；发前复核当前群、店铺授权及通知开关。仅在该群内重算实际可 @ 的已映射负责人，不自动增加群、私发或重放。汇总页有店铺权限变化时取消该冻结页，不发送包含该店的总数。开关关闭不影响其他早报或历史，回滚不删除持久化数据。SparkX 试点与本卡数据源独立。

## 店铺当地「今天」：只读核验，不开推送

负责人问“今天花了多少、卖了多少、退了多少”时，先区分**仓库何时读到这份数据**与**领星实际更新到了几点**。核对本仓库的请求、采集任务和已测试响应后，边界如下：

| 来源 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 产品表现（`product_performance_daily`） | 按单店、起止同一日、ASIN、USD 请求；完整分页后按商品保存显式字段。 | 日期参数可以填今天，不等于响应实时、截止时点明确。已测试产品行没有独立店铺日/供应端更新时间证明。 |
| 店铺利润（`profit_report_daily`） | 单一结算日；验证行内店铺与 `postedDateLocale`；只取 Disbursed 销售退款，不取费用退款。 | 即使有记录，也不代表下单日发生的全部退款，更不含尚未发放的退款。 |
| 08:00 采集、每日采集、经营补采 | 常规目标是已结束的店铺日，经营接口还取对比日；09:00 早报保持原样。 | 最新成功任务或今天完成的昨日分区，均不能证明有今天数据。 |
| 小时广告观测 | 可观察当日 SP。 | 不能补全本卡的全广告花费、净销售额、件数退货率或已发放退款；不加到产品表现。 |

**隔离环境用法：** 准备已核准的范围文件（如 `{"store_ids":["101","102"]}`）与一致、独立、静止的 SQLite 测试/脱敏副本（至少含同一快照的 `stores`、`data_coverage`、`daily_metrics`）。不得复制正在写入的数据库主文件、随意丢弃 WAL，或用陈旧的范围文件授权。没有这种副本时，可先运行合成验收，不要求从生产库导出数据。

```sh
PYTHONPATH=src python scripts/audit_owner_today.py --sqlite-copy /path/to/isolated.sqlite --scope-file /path/to/approved-scope.json
# 用店铺当地日核验指定截点：下面的北京时间与 2026-11-21T17:00:00Z 为同一瞬间
PYTHONPATH=src python scripts/audit_owner_today.py --sqlite-copy /path/to/cutoff-backup.sqlite --scope-file /path/to/approved-scope.json --as-of '2026-11-22T01:00:00+08:00'
# 无需任何数据或凭据的离线验收
pytest -q tests/test_owner_today.py
```

命令只向标准输出打印核验结果；不加载部署配置或业务凭据、不连接生产 MariaDB、不读取领星/飞书接口、不建表、不取数、不写通知队列。默认没有任何任务。输出是内部数据，按店铺范围保管。没有可用库不要拿上一日改日期；合成测试也不是实际店铺业绩。

不传 `--as-of` 时仍按实际运行时刻核验，输出不变。显式回放的 `mode=READ_ONLY_REPLAY`、`reference_cutoff_at`（逻辑参考截点，UTC）与 `generated_at`（本次实际执行时刻，UTC）分别记录；卡片显示的是回放参考时刻。时间须用 `YYYY-MM-DDTHH:MM[:SS[.ffffff]]` 加 `Z` 或已知的 `±HH:MM`，拒绝裸时间、`-00:00` 和未来截点。输入的偏移仅用于定位瞬间，店铺日期仍按各自时区计算。

**副本决定回放能证明什么。** 若要回答“截点当时仓库里有什么”，须留存与该截点对应的一致、只读副本，并在受控位置记录快照对应时刻、备份标识/文件哈希、获准范围及其版本。脚本不会认证副本取得时间或重建历史版本。事后才取得的副本可能已回填或覆盖，即使有行通过时间过滤，也只能说“这份副本按该参考时刻会显示什么”，不能反推当时的金额或认定当时缺数。比较收盘修订时另存同一范围/店铺日/币种的收盘后结果，别用收盘副本替代白天截点副本。

- 每店按副本中有效授权状态与时区计算当地日；不同日期或不同时区单独分组。每张卡标明日期、时区、组内店数和指定范围店数；无店铺或时区证据者单列，不进入合计。
- 只使用目标分区已完成、行数为正、店铺当地同日捕获且不晚于核验截点的同源事实。距截点恰好 90 分钟仍可用，更早或晚于截点的记录不取数。每个店铺/来源分别输出 `warehouse_completed_at`（本地采集完成/失败记录时间，UTC），不是供应端更新时间或统一截止。旧值、未来记录、空响应、失败分区以及缺字段不补零。真实零保留，分母为零不报 0%，货币冲突的退款不并入产品金额。金额分币种列出；件数退货率按有同窗件数的店铺加权。
- `status` 为 `NO_PREVIEW_VALUES` 时只列缺口，不生成金额卡；`PARTIAL_PREVIEW` 中每项标明覆盖；`ALL_METRICS_PROVISIONAL` 也只是指定范围四项均有暂估数值。退出码依次为 2、2、0；文件/库输入错误为 1，缺少必填参数、`--as-of` 格式错误或为未来时刻时为 2（stderr 提示，无报告）。
- 全程 `provider_updated_at=null`、`delivery_enabled=false`。要安排白天推送，仍须独立核实领星同日可用性及数据更新时间/滞后、跨多次截点与收盘后结果的差异，并确定发送时点、店铺范围及如何提示结算滞后。现有曾经成功、样例全绿或手动运行此核验均不满足该上线条件。不新增采集、补采、飞书定时任务或重发；无需数据迁移或回滚数据。
