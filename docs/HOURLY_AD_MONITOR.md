# 08:00 取数、09:00 日报与每小时广告巡检

- 北京时间 08:00 开始采集经营、绩效和商品推广，按已结束的美国太平洋时间统计日保存数据。09:00 按店铺绩效与违规、经营数据、已确认的广告异常依次发送上午快照。先前的分页正在重试时，后续页等待。标题使用北京时间的前一日，正文保留美国统计日。08:00 的任务记录各店目标统计日的店铺、ASIN 和 MSKU 销量覆盖；即使 SP 已成功，缺失的销量分区也会触发现有有界重试。已冻结的日报和已投递分页不因此重发。
- 每天北京时间 18:30 独立排队全店铺采集，回补最近两天销量，并走既有按店检查点及重试。采集计划与小时巡检各自调度；同店同美国统计日的正式 SP 活动报表同一时间只允许一个任务采集。遇到占用或失败按任务状态重试，不将已完整验证的报表降为失败。补采不重新发送已冻结或已送达的日报。
- 每小时更新一次商品推广活动状态、盘中观测及相邻的完整报表分区。失败最多进行两次重试，次小时使用新的任务。每天完整 Excel 归档及手动历史补采继续使用原入口。
- SP 转化使用成熟归因数据，基线优先完整前七日，其次完整前一日。DeepSeek 只复核证据充分的候选。盘中需当天源超预算事件和已核实日预算，默认花费高出 2 倍日预算至少 30 美元。
- 同一活动 72 小时内最多提醒一次。每轮合并通知群表格，@ 涉及的店铺负责人。只有一位已配置的广告总负责人额外接收广告异常私聊。发送前复核活动状态和接收权限。
- 群表格、广告总负责人私聊和 09:00 日报的广告页，每个活动都标“对应运营：姓名”（来自「负责人映射」，未映射显示“未映射运营”）。姓名只作显示，发送前按当前映射重新生成，不增加 @ 或私聊对象。姓名同步见[运营台说明](OWNER_CONSOLE_AI_AND_SPARKX.md#运营姓名负责人映射)。
- 北京时间 08:00 至 18:00 发送即时告警。18:00 至次日 08:00 照常取数、分析并记录确认的异常，当日早上刷新在投状态后合并成一条群消息。没有可确认的异常则保持静默。机器人收到提问后的原消息回复可正常使用。
- 缺基线、归因等待、授权失败和采集失败保留在后台。接口成功返回空记录保留为空记录，失败按来源实际结果记录。运营主动提问仍可查询这些情况。
- 在「负责人映射」维护每个店铺的负责人。在「通知群设置 → 广告总负责人」选择一位群成员。规则、活动级分析指引与去重边界详见[广告分析与飞书通知规则](ADVERTISING_ANALYSIS_AND_FEISHU.md)。

启用私有运行配置中的 `hourly_ad_monitor_enabled` 后，全店铺采集使用 `hourly_mode_daily_sync_cron`（默认 `30 18 * * *`），08:00 早间取数仍由小时巡检处理，日报投递时间仍由 `feishu_daily_report_cron` 控制（本模式通常为 `0 9 * * *`）。关闭小时模式时，全店铺采集仍使用 `daily_sync_cron`。部署前的运行配置备份与对应测试代码一并用于回滚。

## 店铺定向私聊与成熟转化分类（关闭开关时仍用旧投递范围）

- 私有运行配置 `hourly_ad_store_routing_enabled=true`，并设置 `hourly_ad_store_routing_app_id` 为批准用于店铺私聊的飞书自建应用 App ID（不是 App Secret）后，额外私聊仅采用当前店铺的独立授权。旧名册不会自动视为与 App ID 绑定，启用后请用正确应用重新核验并保存。先在「负责人映射」用群成员校验选中**唯一运营**并保存；校验时保存运营名及店铺群成员快照。在私有飞书路由文件的 `stores.<sid>.manager_open_ids` 显式填入该店审批过的负责人 Open ID 数组；这些人也必须出现在该店的 `groups.<alias>.verified_member_open_ids`。「广告总负责人」订阅、全局管理名单和群管理员都不会自动升级为某店私聊负责人。目前管理界面不替你维护 `manager_open_ids`。
- 运营收到自己被明确映射的店铺；负责人收到对其逐一授权的店铺，卡片每条标明实际活动 ID 与对应运营。兼任不重复发，重名不据此查人或授权。未配置、多个运营、离群或名单未经核验时不发相关私聊。仅在原来已启用并验证的日报群兜底时，可保留原群告警且不做不明 @。联系人调整后，已排队旧私聊不迁移、不补发；飞书提交前再次检查当前权限、应用凭据和实际发件应用一致；凭据轮换至另一应用、旧名册、重复 JSON 字段均不能把私聊投到新身份。
- 仍只对已有独立成熟日报、已核实 USD 和足够样本的 SP 活动做小时转化判断，不扩写 SB/SD 数据或当前小时订单。高花费零转化沿用成熟日、真实零和参考预期的保护。高花费低转化还要求实际订单显著少于参考转化推算，且与历史每单成本对比有实质差额，差额不等于实际亏损。低花费零转化必须有连续 3 个成熟日、各日小额、累积花费与点击达门槛、另外 7 个完整成熟日作不重叠基线，且累积花费至少是历史获客成本的 2 倍；小样本不推送。低花费高转化要求多日和实际转化样本、较好的有效 CPA 与 ROAS，只放在「优化机会」段，不作为浪费告警或预算建议。
- 北京时间 08:00–18:00、夜间暂存与翌晨有效性复核规则未改；盘中观测不作为成熟转化依据；未达到归因窗的转化不推送。全部为只读复核，不会改广告活动、状态、预算、竞价或商品。上线前应先用无飞书外发环境核实每店运营、负责人名单和投递收件范围。关闭开关恢复既有路由，新版本私聊草稿不补发，不删除历史。
