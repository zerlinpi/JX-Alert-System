# 早间快报与自然提问

## 北京时间每天08:00

现有日报任务启用 `feishu_morning_focus_enabled=true` 后，发送到运营台选择的通知群：

- 每天发送开启通知的店铺绩效/违规快报：健康评分、源评级、当前是否可判定、待处理违规相关通知、绩效关注项和源更新时间。
- 广告只列存在实质问题的SP活动。名称、具体问题、实际花费日期、成熟归因日期与七项指标分开列示。CTR/CPC/CDR/CPS/ROAS/CPA/TCOAS沿用现有口径、样本与实质门槛；TCOAS只在店铺汇总适用，不伪造活动值。
- 普通波动、改善、单纯花费高、未成熟的零订单，不单独发广告消息。没有活动问题时不发“广告无异常”；不附空的SB/SD。
- 开启精简通知后，授权失败、目标日未采、接口无记录和证据不足可在运营台或向机器人查询。飞书早报只发绩效摘要和实质广告异常页。

报表日按各店已核实的时区或既有保守历史模式计算，不能把北京时间的昨天当成美国报表昨天。广告问题中的报表日和成熟归因日均实际标示。08:00读取已保存数据；不保证领星届时已更新，也不悄悄改成盘中最终值。

未核实时区店铺沿用既有历史回退保护：目标日没有任何尝试、事实或覆盖时，才可复核近七日最近一份完整日报，同时标明目标日、实际复核日和“历史不代表目标日”。目标日失败或已有部分数据时不回退。全店查询明确日期时使用指定日期；未结束日期只提示不能作完整日报判断。

绩效依然**仅观测归档**。无偏移源时间保留原值且源时区为空；无法确认时效时，快报必须写“待确认”。评级良好、评分高、零条归档通知都不能证明当前健康或没有违规。普通待处理通知不直接叫违规；标题明确涉及违规/侵权的只称“违规相关通知待核查”。本次没有启用健康业务告警。

当天首次生成后冻结内容、日期和收件范围，重启或数据更新不重发；升级前当天已有旧版日报也复用原记录。恢复仍遵守08:00和北京当天边界，消息入队不等于实际送达。

## 消息呈现

群内健康快报与店铺清单最多4列，广告关键值使用纵向2列；日期、基准与变化合并到紧凑指标列。去掉采集开关、内部采集UTC时间和全部无值的重复表。真实零保留，原始7项指标和所有维度仍在数据库/Excel，不因消息简化而删除。

单店日报先展示绩效，再展示有值的经营/广告数据。解释、是否违规、为什么等自定义问题可直接用简短文字回答，不强制附整套标准表。没有店铺的业务概念或使用问题也可回答；具体店铺多义、越界或名称未知时继续确认，不猜店铺或执行模型生成的动作。

“今日日报”表示今天展示的最近已结束日的日报；明确的日期不改写。“今天实时数据”仍属于盘中问题，尚未结束时不能当成完整日报。

## 后台手动同步

1. 打开云端 `/console/`，使用已有所有者口令登录。
2. 在经营概览选店，点击「同步最新日报」。沿用当前采集范围、授权和采集开关，无需填写编号或密钥。
3. 页面显示等待、运行、重试及实际报表日；可以点「刷新同步状态」。成功后点「回到最新」查看新保存数据。
4. 同步使用店铺最近已结束报表日及最新绩效观测，不把尚未结束的当日写成最终日报。源无记录仍如实显示，不人为补零，也不因手动刷新额外发群。

页面顶部「一键同步所有店铺数据」会从配置范围中筛选开启采集、授权正常且日期可确定的店铺，一次提交后台任务。关闭、授权失败或资料缺失的店铺按原因跳过，不会自动开启。页面展示总数、已完成、待处理和跳过状态；重复点击复用在途批量任务，失败沿用已有逐店检查点和重试。整批完成前，已保存的店铺数据也可在「回到最新」查看。

所有者已将配置范围内64家店铺的报表时区统一设为 `America/Los_Angeles`。夏令时随IANA规则处理。重放配置可执行 `python scripts/set_us_store_timezones.py --all-stores --apply`。省略 `--apply` 可先预览。脚本使用采集锁并备份配置文件和数据库时区原值。回滚时使用回执中的备份，逐店恢复原时区。

绩效接口无偏移的更新时间继续按源原值展示。精简早报用“时效待确认”说明其可靠性，快报中不单独推送源时间配置提示。

## 可以直接这样问

群里真实@机器人，或已授权用户私聊：

| 问题 | 回复范围 |
| --- | --- |
| 现在有哪些店铺数据 | 当前开启采集或通知的店铺、最近可用报表日、销量/SP真实数据状态及两项开关；直接查库，不耗模型调用 |
| 包含已关闭的店铺列表 | 同时列出已停用店铺的历史状态 |
| 所有店铺的绩效和违规情况 | 当前运营店铺的绩效观测及待确认项 |
| 所有店铺广告有哪些异常 | 有证据的SP活动问题及影响判断的数据缺口 |
| 美国店铺昨天广告花费排名 | 对比同一已结束报表日、币种一致且有完整证据的店铺 |
| 查一下哪些店铺在投SP | 按店铺列出已观测到启用的SP广告，以及保存观测的时间 |
| 哪个店铺销售最高 | 基于同日同币种的已保存销量报表排名，并标明覆盖范围 |
| 最近7天美国店铺销量趋势 | 对比最近7个已结束的日报日并列出逐日数据。多日查询支持至多14天 |
| Geteen美国绩效是否有违规 | 该店绩效证据与分析，不附无关广告表 |
| Geteen美国广告情况 | 广告证据、七项指标与简短分析；空SB/SD不展示，明确问SB/SD时保留状态 |
| 帮我更新Geteen美国的数据再分析 | 识别明确刷新请求，沿用单店采集权限和开关；先返回任务回执，完成后再问该店情况 |

“能否采集”“如何更新”“不要刷新”等不会启动采集。普通群成员查询资格不等于采集资格。明确查询已关闭店铺仍可读取历史；模糊名称匹配多店时优先当前运营店铺，仍多义则列出候选，不猜店。

## 店铺关闭何时生效

运营台两个独立开关保存后共享文件立即生效，无须重启：

- 采集关闭：后续任务、每页请求及退避后的重试会重新检查。已经发给领星的请求可能完成；已提交事实、原始快照和Excel保留。中途暂停记为跳过，不当作失败重新采集。
- 通知关闭：新自动快报排除该店，实际发送前再次检查；包含该店的已排队合并卡片整张跳过。已经发出的消息不撤回，重新打开不补发旧消息。

只关通知不阻止采集，只关采集不阻止读取已保存的观测与通知。明确的群内/私聊查询回复保留，不受自动通知开关限制。

本次核对：64家配置店铺中24家美国店两项开启，40家非美国店两项关闭。此为核对时的配置，不是按国家硬编码；以后以运营台保存状态为准。

## 启用与回滚

云端在现有运行配置开启 `feishu_morning_focus_enabled` 和 `feishu_quiet_delivery_enabled`。飞书只发送北京时间08:00的定时早报、通过实质证据校验的广告异常，以及机器人对原消息的回复。同步进度在运营台查询。采集状态、授权及数据质量通知留在系统，普通报告推送在精简模式下返回跳过原因。定向查看这些内容时可在飞书 @机器人或私聊。

回退精简策略可将 `feishu_quiet_delivery_enabled` 改为 `false` 并重启。回滚到不支持该字段的旧代码时，从运行配置移除该字段再重启。回滚保留数据库、Excel、投递记录和当天已生成的日报。
