# 通知群替换与机器人私聊

## 在运营台替换通知群

1. 在飞书目标群的「设置 → 群机器人」中添加现有 JX 自建应用机器人。
2. 打开 <https://jxmcp.pacefitday.com/console/>，用现有所有者口令登录。
3. 左侧选择「通知群设置」，点击「刷新群列表」。这里只列出机器人已经加入的群，不搜索企业所有群，也不列私人会话。
4. 在「替换为」选择目标群，点击「查看替换范围」。同名群会显示编号末六位，需核对后再选择。
5. 查看原群与新群、管理员保留/移除人数、群外负责人数量。确认无误后勾选确认框，点击「保存通知群」。

保存后，无须重启机器人，后续日报、默认群提醒、Chat报告及该群的@问答使用新群。当前64店都使用此通知群别名；将来另设独立群路由的店铺或商品仍沿用其独立配置。管理层私信、店铺采集/通知开关、领星数据和MCP权限不变。

负责人映射保留。新群内@只保留已核实成员；不在新群的原管理员从该群管理员映射移除，不自动指定新群主为管理员。缺少人员且已启用群兜底时直接发群、不造@。新成员加入后，可重新选择当前群并预览/保存以刷新名单，或保存对应店铺负责人映射时刷新群成员名单。

切换前旧群待发消息保留为`SKIPPED`，不移动正文、不补发到新群；切回原群也不恢复旧消息。已经发出或已经进入发送请求的消息不能靠切群撤回。不会主动重建或重发今日已送达日报。旧版未保存群别名的排队消息按原群退役时间保护；同一旧群被多个别名复用时，无法区分的旧消息也保留而不冒险发送。

群列表、详情和成员必须读取成功才允许保存；权限不足、配置版本冲突或读取失败时保留原配置。保存有所有者登录、同源/CSRF校验、限频、版本比较、文件锁及修改前私有备份。

## 私聊机器人

在飞书点击机器人的头像或从应用中打开机器人，点击「发消息」，直接输入，例如：

- `Geteen美国的广告和店铺绩效，只列异常和待确认项`
- `川页美国 2026-11-13 的广告指标`
- `实时采集 Geteen美国`
- `Geteen美国采集进度`

私聊不需要@，回复引用原消息并留在该私人会话，不推到通知群。群内仍需在当前通知群真实选择@该机器人。店铺全名、品牌及模糊名称解析、歧义确认、中文数据表、七项广告指标、成熟度/缺失保护与原有问答一致。

私聊仅向已配置的管理员、运营/管理层，或经飞书成员接口核实的当前通知群成员开放读取。不是只要能打开应用就能读取全部经营数据。读取成员失败时等待重试，不把未知身份当作已授权；无权用户不生成经营数据回复。普通群成员只获得查询能力，实时采集仍仅限当前管理员或该店铺已映射负责人，并保留采集范围、开关、日期和授权检查。

消息、发送者与会话身份随任务保存；分析前、回复入队前和实际投递前检查权限。私聊缓存不跨发送者复用，采集回执不跨私人会话或发送者查询。原ChatGPT MCP继续独立运行，不依赖DeepSeek响应完成。

## 飞书后台需要的权限

如私聊没有任何回复，检查自建应用的以下配置。只需原来的「接收消息」事件，无需新建Webhook。

1. 进入飞书开放平台 → 现有自建应用 →「权限管理」。
2. 保留群@读取`im:message.group_at_msg:readonly`、发消息`im:message:send_as_bot`、群成员读取`im:chat.members:read`。
3. 增加/确认 **获取用户发给机器人的单聊消息**：`im:message.p2p_msg:readonly`。
4. 查看群列表需要`im:chat:read`，或应用已有的同等群信息读取权限（如`im:chat:readonly`）。不要为这个功能申请读取所有群消息。
5. 「事件与回调 → 事件配置」沿用「使用长连接接收事件」及「接收消息 v2.0」`im.message.receive_v1`。
6. 「版本管理与发布」创建并发布新版本，完成企业审批；只有勾选权限而未发布不算生效。应用可用范围也须包含实际提问者。
7. 用真人私聊发送一个店铺问题，核对是否收到数据表；通过后台任务与`DELIVERED + message_id`核对送达。测试用例通过或长连接在线不能代替真人私聊验收。
