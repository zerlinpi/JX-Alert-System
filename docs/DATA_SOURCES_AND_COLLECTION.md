# 数据源管理、双源采集与私聊实时观测

## 后台添加和按月更新

1. 打开 https://jxmcp.pacefitday.com/console/ ，使用既有所有者账号登录，进入「领星数据源」。
2. 接口填写领星开放平台的App ID及App Secret；可选填写不同的App Key或静态Access Token。使用原接口身份只更新日期时，可以留空现有凭据。更换App ID必须同时填写新身份的App Secret或Access Token，不继承旧身份秘密。
3. MCP填写官方Server URL `https://openmcp.lingxing.com/mcp-servers/lingxing-mcp` 及 X-Mcp-Key。请在领星ERP的AI助手→MCP复制密钥，不要把密钥发送到聊天或GitHub。
4. 核对计划更换日期。界面默认建议一个日历月后，月底会落到下一月的最后一天；这是所有者设置的更换计划，不是推测领星承诺的有效期。填写日期按美国太平洋时间当日结束后停止使用旧配置，并尝试其他可用源。留空则不设置本地到期限制。
5. 点击保存，查看「添加与更新记录」里的时间、数据源和计划日期。记录不含App ID、密钥或Token。更新日期也属于配置更新，不冒称密钥本身已更换。
6. 后续采集自动读取新配置，无需重启。可以在后台手动同步单店或全部允许采集的店铺。配置已保存不代表上游授权已经验证，实际结果以采集状态与数据为准。

所有报表日期沿用 `America/Los_Angeles`；后台配置事件也按美国太平洋时间展示。每天08:00日报、18:30采集、23:30Excel归档仍按既有北京时间调度。领星返回的无偏移健康源时间继续保留原值，不凭店铺报表时区推测其实际时区。

凭据只进入既有HTTPS所有者后台，不回显、不写浏览器本地存储或查询地址。服务端保存到权限为0600的私有文件，并使用原子替换、跨进程锁及版本校验。旧.env、数据库、Docker卷和历史文件保留。每次接口配置更新使用独立Token缓存，防止新凭据继续使用旧身份Token。页面过期或版本冲突时请刷新并重新填写，系统不会自动覆盖其他人的更新。

## 两种来源如何配合

| 可用来源 | 处理 |
| --- | --- |
| 只有接口 | 沿用原接口采集与分析 |
| 接口和MCP都有 | 接口保留原有权威日报；MCP补充经营看板及独立观测，留存各自响应和来源 |
| 接口失败、MCP成功 | 展示MCP已确认的对应日期数据，明确其口径；不把旧接口数字冒充本次新数据 |
| MCP失败、接口成功 | 保留成功接口结果，记录次源问题，避免重复重跑完整成功管线 |
| 都失败或权限不足 | 保留历史证据，标记本次失败，不制造零值或广告正常结论 |

综合数据指互补和核对，不是相加。现有接口销量统计包含实际付款口径，MCP产品表现是下单口径；两者独立保存，不跨口径计算环比、凑差额或套用原付款订单告警。MCP广告报告里未确认币种、转化归因窗口的金额或转化指标不会进入成熟广告告警。后台与机器人只展示可核实的字段。

MCP先核对固定查询工具的只读声明、参数结构和可见店铺。不能凭MCP可见性恢复亚马逊授权，也不访问未授权店铺。接口权限失败、MCP权限失败、空结果、真实零及缺采状态仍分别保存。

接口22日归因刷新保留原机制；MCP不为未知归因窗口重复抓取全部历史来构造基线。查询复用已核实的结构与同次采集缓存，遵守官方工具频率限制。某一来源失败不把另一来源已经提交的分区改成失败。

## 机器人私聊实时采集

已授权管理员或店铺负责人可私聊机器人，用店铺名或名称片段明确请求：

- 「刷新Geteen美国最新数据」：重新获取最新可用的完整日报，沿用原队列、重试和店铺开关。
- 「实时采集Geteen美国今天的广告」：获取当前SP广告观测；不会把当天尚未结束的数据当作完整日报。
- 「Geteen美国采集进度」：查询该私聊用户的任务回执，无需输入编号。
- 「Geteen美国今天广告花费和点击」：读取已有的最新SP盘中观测，并保留观测时间。

今日观测目前针对SP广告，不代表今日销量、库存或全部经营维度均已实时接入。它使用独立的原始响应、JSON及Excel，不覆盖完整日报事实、采集覆盖或历史基线，也不触发业务告警和群通知。后续观察失败时，不把上次成功观测冒充最新结果。

群内普通提问保持原回复功能，实时采集引导到私聊。采集需要明确请求、会话及发送者权限，并在执行前复验店铺范围和采集开关；模型不能自行选择写操作。队列受理、数据采集完成和飞书消息送达是三个独立状态，只有实际送达记录才能证明通知已发送。

未取得广告金额、订单、库存、补货交期或搜索词明细时，不猜测花费、断货时间或浪费词。缺失字段从报表和回复中省略；无法回答整个问题时只给出具体阻塞与可执行的下一步，不把未知写成正常。原有七日基线、前一日回退、成熟归因、实质告警门槛和通知静默策略保持。

## 保存与回滚

来源响应保存在原始快照中；MCP观测独立使用`mcp_*`维度，既有付款和广告事实不被覆盖。所有新维度进入既有每日Excel全历史归档。重复采集更新当前版本，保留原始版本，不重复累加花费。

回滚只切回已测试代码及对应控制台镜像，保留私有凭据文件、审计记录、数据库和Excel。凭据本身如需更换，由所有者在后台重新填写；不会通过回滚把已经更换的秘密公开或写回.env。

官方连接说明：https://www.lingxing.com/help/article/mcp 。库存、现金流、搜索词等尚未完整接入的场景不因新增MCP连接而自动宣称可用；每个新增数据维度仍需独立验证。
