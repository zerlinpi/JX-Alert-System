# 管理员上传自己的 Skills

在管理台打开 **分析设置 → 自定义 Skills 资料库**。选择电脑里的 `SKILL.md`，点击上传。同名技能的新内容成为新版本，初始状态始终是「停用」。点名称预览原文与版本摘要后，可将当前版本标为「可用」。可用仅指文档通过管理员审阅，**不是已应用到模型**。

首次上传可在页面展开「第一次上传？查看文件格式与示例」，复制并另存为 `SKILL.md`。下面是一份带可选分析目标的完整示例：

```markdown
---
name: mature-ad-review
description: 在人工复核广告效率前检查数据是否完整以及归因是否成熟。
metadata:
  jx-review-objective: efficiency
---
# 成熟广告复核
检查币种、报表日期和归因窗口。缺少数据时不要把缺失订单当作零。
```

## 文件格式、可移植性与实际作用

- 支持 [Agent Skills 文件规范](https://agentskills.io/specification) 的单文档安全子集：UTF-8，最大 16 KiB，YAML 声明区和非空 Markdown 正文。必填 `name`（最多 64 个小写英文字母、数字及分隔用的单个连字符）、`description`（最多 1,024 字符）。`license`、`compatibility`、小型纯字符串 `metadata` 可选；不支持 YAML 标签、别名、嵌套元数据、重复键或工具权限字段。数字版本请加引号。
- 在详情里点击「导出此版本 SKILL.md」可下载保留原文和换行的文件。其他**支持该单文件格式**的适配器可按自己的导入规则使用；需要目录时把文件放在和 `name` 同名的目录下。不承诺所有模型原生支持、已受测或表现相同。不会自动将资料发给 DeepSeek、ChatGPT 或任何其他模型。
- `metadata.jx-review-objective` 可选，只接受 `balanced`、`efficiency`、`reach`、`discovery`。仅对已审阅、可用的当前版本显示本地结构化预览。文档没有此字段也可保存。若需要改变已有 JX 广告分析默认策略，请使用**独立的内置策略面板**明确选择，不从上传文档自动改规则。
- 上传不是安装软件。ZIP、脚本、包含多文件的包、工具声明、URL 拉取与供应商工作流不受支持。正文中的代码块、HTML、网络链接和自然语言均按原文展示，不运行、不读取依赖、不追加进系统提示词、不发通知、不授权任何操作。不要在文档中放入密钥或个人数据。

## 版本、存储与回滚

- 每个操作绑定所见资料库版本。详情提供原文、SHA-256、时间、版本列表和最近 30 条审计记录；相同内容重试不重复建版。旧版回滚和启停不会删除历史；恢复不同版本后必须重新审阅。最多 32 个技能，每个技能最多 16 个唯一内容版本；到限会拒绝写入，不覆盖旧数据。
- `AGENT_SKILL_LIBRARY_DIR` 默认 `/app/data/owner-skill-library`；空字符串关闭。要求已有的持久化父目录；SQLite 文件由管理台创建在独立的私有目录（POSIX 0700，数据库 0600）。不要指向源码、静态资源、其他 SQLite 文件、网络共享或自动发现技能的目录。上传文件从不写到可导入代码或静态资源路径；没有 MCP 工具、定时任务或运营写入端点。
- 更新前备份持久卷。可先停止 console，然后备份完整资料库目录，再重启；有其他写入方时不要仅复制活动 SQLite 主文件。回滚功能版本仅需恢复已测试的旧代码，保留数据目录/卷；回到该版本后可重新读取资料。
- 仅所有者 HTTPS 控制台会话可读，写入还需同源、CSRF 和限流。请求体收完并开始保存前会再次验证会话：若已退出或过期则拒绝写入。接口：`GET/POST /console/api/skill-library`，`GET /console/api/skill-library/{name}?version=N`（不传版本即当前）。入库、版本指针、启停状态和审计在同一个 SQLite 事务中提交。审计记录身份为该单所有者管理台账号，不记录正文到日志。

自动验证：`pytest -q tests/test_admin_skill_library*.py`；`node scripts/verify_skill_library_ui.cjs` 验证组件交互（模拟 DOM，不替代浏览器验收）。这些测试使用隔离临时存储，不连接模型、飞书或真实广告系统。
