# 管理台

地址：`CONSOLE_PUBLIC_URL` 的 `/console/`（HTTPS）。用所有者口令登录（沿用原 `mcp-owner.json`，口令不变）。登录状态随使用自动续期：每次操作都把有效期延长到 12 小时后，连续 12 小时没有任何操作才需要重新登录；从登录起最长 7 天。点「退出」立即失效。所有写操作都需要同源请求和页面令牌。

## 页面（左侧导航）

| 页面 | 作用 |
|---|---|
| 概览 | 「开始使用」清单（未完成的步骤直接跳到对应页面）；SparkX、DeepSeek、飞书发送、店铺状态；三条通知的开关与最近一次运行；最近发送 |
| 店铺与运营 | SparkX Token 授权的店铺。搜索；按「未指定运营」「未纳入通知」和站点筛选；勾选多家店铺（可全选当前筛选结果）后批量指定运营、纳入或暂停通知；每行可单独编辑运营（通知群成员，最多 10 位） |
| 通知与报告 | 通知群和负责人；三条通知各一张卡片：开关、发送对象（含「群内 @ 对应运营」）、频率/时段、提醒阈值、DeepSeek 任务说明（可改写、可恢复默认）。修改后底部出现「有未保存的修改」，可撤销或保存。「预览」用当前（含未保存的）设置在后台让 DeepSeek 查询 SparkX 并生成卡片，不会排队或发送；「测试发送」打开同一个预览，生成后可把它发到通知群或负责人（见下文） |
| SparkX MCP | 保存或清除 MCP Token（只写不读）、测试连接并列出授权店铺；安装 / 更新 / 检查官方 Skills；勾选使用哪些 Skill（见下文）；查看提供给 DeepSeek 的只读工具 |
| DeepSeek 与机器人 | API Key（只写不读）、模型、单次请求超时、深度思考开关；测试连接只调用免费的模型列表和余额接口；飞书机器人使用说明 |
| 发送记录 | 最近 30 条通知和问答回复的状态（Excel 文件单独一行，标题「Excel：文件名」）；「Excel 存档」下载最近 80 个 Excel 文件 |
## 官方 Skills 的选择
- 「安装 / 更新」安装官方清单里所有只读 Skill（2026-11-25：11 个）。需要写入工具的 Skill（创建/编辑/删除广告与托管组、词库、SQP 洞察、大促准备/监控/复原）按只读规则不安装，表格里写明需要哪些写入工具。
- 每个已安装的 Skill 前有「启用」勾选框，勾选或取消立即保存，下次运行（三条通知和飞书问答）生效。三个基础查询 Skill（广告效果、实体配置、操作日志）始终启用：DeepSeek 调用 SparkX 前必须读它们。
- 状态「需开通工具」：Skill 已启用，但当前 SparkX Token 没有提供它需要的工具（市场数据、类目记分卡、ASIN 深挖需要 SparkX 的 `sqp:read` / `benchmark:read` 权限）。这时 DeepSeek 不会看到这个 Skill；在 SparkX 后台为 Token 开通权限后自动可用。

## 首次配置顺序

1. 「SparkX MCP」保存 Token →「测试连接」→「安装 / 更新」官方 Skills。
2. 「DeepSeek 与机器人」保存 Key 并测试。
3. 「店铺与运营」→「从 SparkX 刷新店铺」。Token 授权了很多店铺时，用搜索（例如「加拿大」）+ 全选 →「暂停通知」只保留需要的站点；再为店铺指定运营（可以稍后再指定）。
4. 「通知与报告」确认通知群，选择总负责人和广告负责人（各可多选，最多 10 位）。
5. 逐个「预览」核对内容（每次约 1–10 分钟，会消耗 DeepSeek tokens），需要时改写任务说明后再预览、保存；满意后在预览窗口底部「发送测试」，到飞书里看实际效果。三条通知默认全部开启：实时监控在发送时段内每小时运行，日报和复盘在 08:30–10:00 生成。
6. 服务器 `.env` / 运行配置中 `APP_DRY_RUN=false`、`FEISHU_ENABLED=true`、`SCHEDULER_ENABLED=true` 后才会真正发送。

店铺不必全部指定运营才开始使用：未指定运营的店铺照常发到通知群（标注「未映射运营」）；指定之后，群消息会 @ 出问题店铺的对应运营。

## 预览与测试发送

- 预览在服务器后台生成，结果保留 30 分钟。生成中关闭窗口不会中断；再点「预览」继续看进度，生成好了直接显示，不会重新调用 DeepSeek。通知卡片的按钮旁会显示「预览生成中（已用 X 分）」或「已生成预览 · 时间」。
- 只有任务说明或（实时监控的）阈值变化才会生成新的预览；只改开关、发送对象不会。窗口底部「重新生成」按当前设置和最新数据重新生成。同一时间只生成一份预览（与定时通知共用 SparkX Token），另一条通知正在生成时会提示是哪一条；正在生成的是修改前的设置时，窗口会提示。
- 「发送测试」：勾选通知群和/或负责人（未设置的负责人不能勾选；有多位时每一位都会收到），可选「@ 对应运营」（列出这份预览会 @ 的人和店铺）。发送的是服务器保存的这份预览，标题带「【测试】」，后面跟同内容的 Excel；不计入定时发送，不影响实时监控去重；同一份预览发给同一对象只发一次。结果在「发送记录」里标注「（测试）」。

## 文件

| 文件 | 内容 |
|---|---|
| `data/secrets/sparkx.json` | SparkX Token（0600）。文件损坏或权限不安全时停用 SparkX，不回退到其他凭据 |
| `data/secrets/deepseek.json` | DeepSeek Key、模型、超时、深度思考开关（0600） |
| `data/sparkx-skills/` | 官方只读 Skills（`installed.json` 记录版本与提交），从 GitHub 安装，不在代码仓库里 |
| `data/sparkx-stores.json` | 每个 Profile 是否纳入通知和对应运营（0600） |
| `data/jx-notifications.json` | 三条通知的开关、发送对象、阈值和任务说明（0600；任务说明为空表示使用默认） |
| `data/feishu-routing.json` | 通知群、总负责人（`company_executive_digest`）、广告负责人（`ad_alert_subscribers`）。多位负责人时第一位仍写在原位置，其余在 `more_recipients`（回滚到旧版本时第一位仍能收到）。每次修改前在同目录留存完整备份 |
| `data/sparkx-skills/choices.json` | 停用的选装 Skill（0600；没有这个文件表示全部启用） |
| `data/reports/` | 每条通知消息的 Excel 文件（按通知和月份分目录，0600，不删除） |
| `data/secrets/console-sessions.sqlite3` | 管理台会话（只存令牌哈希；`session_starts` 表记录登录时间，用于 7 天上限） |

SparkX 授权店铺列表的快照保存在数据库 `sync_jobs`（`job_type=sparkx_roster`），SparkX 暂时不可用时管理台仍能显示店铺。
