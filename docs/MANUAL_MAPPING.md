# 后续需要手填的店铺、负责人和 MCP 配置

本文只说明需要人工确认的映射，不修改服务器配置。配套的 [jx-mapping.example.json](../config/jx-mapping.example.json) 是**汇总示例，不是可直接加载的运行文件**。空字符串和空数组表示尚未确认，不能用示例覆盖已有有效配置。

目前只确认店铺 SID `5174` 使用 `America/Los_Angeles`。这不代表其他店铺也使用该时区，也不代表绩效健康接口的源时间使用该时区。群目的地已在服务器配置；管理员、运营、管理人员 Open ID 仍需补齐。MCP 独立域名由使用者后续提供。

## 配置放在哪里

服务器项目目录为 `/opt/jx-alert-system`，容器中的 `/app/data` 对应服务器的 `data/`：

| 内容 | 位置或运行设置字段 |
| --- | --- |
| 功能开关、非敏感路径 | 服务器 `/opt/jx-alert-system/data/runtime-settings.json`；容器 `/app/data/runtime-settings.json` |
| 当前店铺范围、时区、SP 目标和飞书映射 | 服务器 `/opt/jx-alert-system/data/sp-runtime/`；容器 `/app/data/sp-runtime/` |
| 实际店铺范围文件 | 以运行设置 `collection_scope_file` 当前指向为准 |
| 实际店铺时区文件 | 以 `store_timezones_file` 当前指向为准 |
| 实际 SP 目标文件 | 以 `sp_validation_targets_file` 当前指向为准 |
| 当前飞书映射 | `/opt/jx-alert-system/data/sp-runtime/feishu-routing.json`，由 `feishu_routing_file` 指向 |
| 应用凭据、OAuth 口令哈希及私有状态 | `data/secrets/`，与上述映射分开，不加入 Git |

保留现有 `.env` 和数据文件。填写前只核对非敏感运行设置中的路径，不读取或复制密钥。不要删除店铺范围文件或把其路径留空：旧兼容行为在范围文件不存在时可能采用全部授权店铺。运行设置被进程缓存；修改开关或路径后，由维护者按现有部署流程重载对应进程，不重建数据库或数据卷。

## 依赖顺序

1. 确认要启用的店铺 SID、各自真实 IANA 时区和币种，再填写店铺范围和时区文件。
2. 从已同步广告活动中选择需要详细采集的 SP 目标，填写店铺 SID 与活动 ID。
3. 保留已配置的测试群，补齐管理员、运营和管理人员的真实 Open ID；需要时增加商品级负责人。
4. 在明确选择的群内验证一次新消息的目的地和实际提醒对象，再按正常流程启用后续发送。新异常是否发送仍受运行开关和任务调度控制。
5. 单独确认健康接口源时间的时区；未确认时留空，不从店铺时区或服务器时区推定。
6. 准备 MCP 独立域名、DNS 和 TLS，再通过私有交互初始化 owner 登录口令，最后配置公网 OAuth 入口并验证授权。

## 店铺与 SP 目标

- `collection_scope_file` 中的 `store_ids`：只列需要启用的真实 SID，目前已确认的范围是 `5174`。
- `store_timezones_file` 中的 `stores["SID"].timezone`：填写经确认的 IANA 名称。SID `5174` 可填 `America/Los_Angeles`，其他店铺必须分别确认。系统据此选取已经结束的店铺当地日期。
- `stores["SID"].currency_code`：确认后填写三字母币种代码；不知道时留空并显示未知，不根据名称或国家猜值。
- `sp_validation_targets_file` 中的 `targets`：每项填写正整数 `sid`、`campaign_id`，不得重复，且 SID 必须在启用店铺范围内。汇总示例中的 `141469378857743` 是此前实际验证过的活动，不代表已经选中店铺内全部活动。

日报及成熟归因分析按已完成的当地日期执行；小时 Stream 数据单独观察和对账，不能替代日报，也不能给缺失日期补零。

## 飞书群和负责人

Open ID 必须是当前自建应用下的真实 `ou_...` 标识；不能填姓名、手机号，或用另一种用户 ID 代替。群会话 ID 使用真实 `oc_...`。示例不提供任何人员或群 ID。

| 字段 | 手填内容及作用 |
| --- | --- |
| `groups["test"].chat_id` | 已选择测试/报告群的实际会话 ID；服务器已有值应保留 |
| `groups["test"].admin_open_ids` | 该群需要被提醒的管理员 Open ID 数组 |
| `stores["5174"].chat_id` | 群别名，如 `test`，必须对应 `groups` 中的键；这里不是 `oc_...` |
| `stores["5174"].open_ids` | 该店铺运营负责人 Open ID 数组 |
| `entities["5174:实际MSKU或ASIN"].open_ids` | 可选的商品级负责人数组；将示例键替换为已同步的真实 MSKU 或 ASIN |
| `management.open_ids` | 独立接收管理单聊的人员 Open ID 数组 |

商品级 `entities` 映射确实由路由代码支持。优先采用带 SID 的键，避免不同店铺的相同 SKU 相互影响。负责人来自店铺映射、匹配的商品映射和已保存产品负责人，并会合并去重；**增加商品映射不会自动移除店铺映射中的人员**。如果要细分职责，应同时审查店铺层数组，不能把商品条目当作覆盖规则。

活动告警只从该店铺、广告类型和活动实际关联的商品中解析负责人；系统不会根据活动名称猜人。产品负责人也可以通过现有 `scripts/set_product_owners.py` 保存到数据库，维护时应与文件映射一致，避免重复维护产生额外收件人。

异常群提醒要求管理员和运营映射均可用，缺少者使对应群投递进入 `ROUTING_FAILED`；管理单聊是独立投递，缺少管理映射只阻止该角色。未知 ID 保持空数组。日常测试/报告快照只发送到明确配置的群，不以补齐运营映射为前提，也不表示异常提醒映射已经验证完成。

## 填完映射后，历史失败记录怎么处理

补齐文件**不会自动发送历史 `ROUTING_FAILED`**。普通发送 worker 只处理可发送或重试的记录，不会批量重放这些映射失败记录。

需要补发时，先选定具体 outbox ID，核对店铺、事件时间、告警是否仍有效、内容是否过期、群和人员是否正确，以及其他角色是否已投递。确认后由维护者调用现有 `repair_application_notification` 修复该条失败角色；不要一次性修复全部历史记录。

修复成功会保留原记录并生成对应可发送任务，随后正常 worker 可以发送。因此选择 repair 本身就需要先完成时效和收件人审核。已经成功的其他角色不会因为修复这一角色而重复发送。只想验证新映射时，使用明确的新测试消息，不借用过期业务告警。

## 健康接口的源时间时区

`lingxing_performance_source_timezone` 解释健康与业绩通知接口中不带 UTC 偏移的 `update_date`、`lastUpdateDate` 等源时间。它与广告报表时区是两个独立配置。

未获得来源确认时保持空字符串。采集到的原始观测仍可保存，但 `NOT_CONFIGURED`、`UNKNOWN`、`STALE`、`FUTURE`、`MISSING` 等非 `FRESH` 状态只产生数据质量提示，不新发或恢复健康风险、待处理通知的业务告警。通知分页须全部通过新鲜度检查。是否启用观察采集由运行开关管理，不能把填入一个猜测时区当成验收。

## MCP 域名与私有 owner 登录

后续需要提供一个专用于本服务的域名，并依次完成：

1. 将 DNS 记录指向实际服务器；只发布确实可达的 IPv4/IPv6 地址。
2. 为该域名配置有效 TLS 证书和 HTTPS 反向代理，后端继续使用本机监听。代理必须覆盖 MCP、OAuth 元数据及授权/令牌/owner 登录所需路由，不能只转发一个 `/mcp` 路径。
3. 将 `mcp_public_url` 设置为该域名的 HTTPS origin，不含用户凭据、查询参数或额外路径；默认 MCP 资源地址由它与 `mcp_path`（通常 `/mcp`）组合。相关允许主机/来源也须与实际部署匹配。
4. 通过维护者提供的私有交互 setup，在不回显的提示中输入 owner 口令，不放入命令参数、聊天、`.env`、示例或 Git。模块 `create_owner_credentials` 要求至少 16 字符，首次创建时仅写入带随机盐的 PBKDF2-SHA256 哈希，不生成默认口令、不覆盖已有 owner 文件。
5. owner 文件默认是容器 `/app/data/secrets/mcp-owner.json`；OAuth 状态库默认是 `/app/data/secrets/mcp-oauth.sqlite3`。服务器对应目录均为 `/opt/jx-alert-system/data/secrets/`。文件权限为 `0600`，目录由服务运行用户保护；两者都不加入 Git，也不输出其内容。
6. 域名、TLS、私有文件准备好后，维护者再选择 OAuth 模式并验证登录授权。读取权限与触发采集权限分开；采集请求还要求对应授权、`mcp_operations_enabled` 开关和运行中的调度器。

口令哈希文件不是可以公开的配置模板，OAuth 状态库也不是可以分享的普通业务数据库。域名尚未提供、私有 owner 文件尚未创建或授权未验证时，不应声称公网 MCP 已可使用。

## 自动同步的内容不需要手工抄录

店铺名称与平台标识、广告活动名称/状态/预算、广告组及广告商品关联、MSKU/ASIN、日报和小时指标、健康指标及通知原始记录，都由已授权的只读接口采集。无需把它们抄进汇总示例，也不在此修改广告预算或状态。

采集时间、请求链路、原始快照、历史版本、对账差异、任务与通知投递状态由系统记录。需要人工决定的是启用范围、经核实的时区/币种、详细采集目标、人员职责和公网接入信息。系统不会自动推断这些决策。
