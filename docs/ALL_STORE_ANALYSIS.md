# 全店铺历史分析与日报

## 范围与状态

`collection-scope.json` 是唯一启用范围，不能把已映射运营等同于数据已接入。
`get_analysis_plan` 按店铺返回授权状态、实际时区是否确认、日期依据、基线缺口、
可采集及可分析状态。无数据、数据不足、授权失效与正常无异常分别记录。

官方店铺清单与广告账户清单均未返回卖家报表时区。不能把站点国家、广告币种或
另一个 DSP 账户时区当成卖家实际时区。5174 保留已确认的美国太平洋时间。

用户明确启用的 `allow_unconfigured_timezone_history=true` 允许其他正常授权店铺
先做保守历史分析：取 UTC-12 日历的前一日作为全球已经结束的日期下界。
这只是日期安全边界，**不是店铺时区**；数据库时区仍为空，小时采集与日内分析关闭。
该边界可能比真实当地完整日期保守1至2个日历日。金额使用实际销售返回的唯一币种，冲突会阻止覆盖；
不同币种不能相加，未知币种不能生成金额异常通知。

## 初次启用与回补

先暂停调度容器，确认没有运行中的采集任务，再在现有 app 容器运行：

```bash
docker exec jx-alert-app-1 python /app/scripts/enable_all_store_analysis.py
docker exec jx-alert-app-1 python /app/scripts/enable_all_store_analysis.py --apply --allow-conservative-history
```

第一条只检查实时店铺数量和授权状态；第二条备份并原子更新三个非敏感配置文件，
保留已确认时区、运营映射、私密配置、数据库历史和健康观测限制。
脚本以 app 用户写文件，不能用 root 改变私有数据目录文件的所有者。
结果写入 `data/verification/all-store-activation-*.json`。不修改 `.env` 或广告设置。

通过 `request_collection(backfill_days=8, idempotency_key="all-stores-baseline-20261113")`
排队一次初始回补，再恢复调度。任务按店铺隔离失败，完成的店铺和日期立即持久化为检查点，
重试跳过同日期已完成部分，跨日期不能重用旧检查点。没有完整8日基线时，空分析结论为
`INSUFFICIENT_DATA`，不会被描述为“无异常”，也不发群消息。

广告日报仍按已配置归因刷新窗口回补。已有 SP 小时验证目标保持显式范围，
不会因启用全店铺而自动扩大至未验证活动。成功保存和分析全部数据需用实际任务结果验收。

## 中文日报

`feishu_daily_report_group_digest=true` 对多个店铺的定时 app 日报按10个店铺分页。
表中分别显示店铺、报表日期、订单、销量、销售额、三类广告花费和数据状态。
授权失效、不完整或无记录显示未知；真实明确零值保留为零。金额逐店标明币种。
不生成混合币种合计，也不向群发送长篇过程解释。
金额展示和环比必须有指标本身的明确币种；不能把销售币种套给广告。
广告记录没有币种时保留原数值存档，日报标“未知（币种待确认）”，相关金额异常提交保持阻塞，
待通过官方广告账户信息与报表粒度核实币种后再启用；不回写猜测币种。

北京时间07:00采集、08:00提醒分别调度；全店铺配置不改变这个时间。
首次日报由现有启用日期限制。首次生成的分页范围、内容和投递状态持久化后重试复用，
不因重采或范围变化重发已送达页面。当天旧格式已排队时不额外再排新格式。

## 仍需完成的外部事项

- 领星授权失效的店铺需要在领星重新授权；系统保留阻塞状态。
- 其他店铺的实际报表时区待官方证据，不以国家默认值替代；确认后逐项更新
  `data/sp-runtime/store-timezones.json` 中 `stores.<店铺ID>.timezone`。
- 运营已映射到群内唯一核实的“皮泽霖”；管理员与管理层如需对应投递，仍由用户明确填写
  `data/sp-runtime/feishu-routing.json` 的 `groups.test.admin_open_ids` 与 `management.open_ids`。
- 用户在 ChatGPT 发起新的 OAuth 登录并实测调用。每小时任务需在实际账户验证可使用本插件、
  后台通知权限及真实执行记录；服务端定时采集不等于 ChatGPT 定时分析已运行。
- 健康源时区保持为空且仅观测归档；历史候选误报率需人工标注，领星差异口径待官方确认。

## 回滚

代码回滚至已验收的上一主分支提交，恢复本次生成的非敏感配置备份，再重启对应服务。
保留所有新增数据库观测与通知日志，不删表、不删除数据卷、不覆盖私有凭据。
回滚到不支持未知时区历史模式的代码前，必须把启用范围和时区文件同时恢复为原范围。
