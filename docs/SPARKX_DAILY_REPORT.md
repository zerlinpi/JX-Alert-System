# SparkX 广告日报与广告异常（08:30）

每天北京时间 08:30，JX 用 SparkX 直出数据生成两张飞书卡片：

1. **SparkX 广告日报**：站点汇总（站点、币种、店铺数、有数据、花费、销售额、销量、订单、ACOS、ROAS、CVR、CPC、TACOS、花费环比、销售额环比）+ 各站「N 个有花费店铺明细」（店铺、运营、花费、销售额、销量、订单、ACOS、花费日环比）+ 须知。
2. **广告异常 · 近 7 日对比前 7 日**：一句话结论和整体花费/销售/ACOS 变化；一、最严重（全店零曝光）；二、异常店铺总览；三、按问题类型看具体 campaign（① 高花费零出单、② ACOS 明显恶化、③ 加预算后销售反而下滑、④ 异常停摆）；四、建议动作。

全部只读：只调用 SparkX 的 `get_user_authorized_context`、`get_ads_perf` 和 `get_entity_metadata`，不会调用任何改广告、预算、竞价的工具。建议动作只是给运营的文字建议。

## 开启步骤（运营台 → 分析设置）

1. 「SparkX MCP 连接」：粘贴只读 Token 并保存，点「测试 SparkX 连接」。测试结果下方点「把以上全部授权店铺填入允许列表」，再保存（只统计允许列表里的店铺）。
2. 「SparkX 日报与广告异常」：点「读取 SparkX 店铺并生成建议」。系统按店铺名在同一站点里给出 SparkX 店铺 → JX 店铺的建议（例如“香港川页”→“川页-US”），核对后点「采用全部建议」，不对的逐行改，然后「保存设置」。运营来自「负责人映射」，没有对应的店铺显示“未映射运营”。**未保存的建议不会用于通知。**
3. 选择发送对象并勾选「启用」：
   - 广告日报：公司日报总负责人（私聊，默认开）、通知群（默认关）。
   - 广告异常：通知群并 @ 涉及店铺的运营（默认开）、广告总负责人私聊全部店铺（默认开）、各运营私聊只含自己的店铺（默认关）。
   - 「08:30 公司日报数据源」选 SparkX 时，领星版 08:30 公司日报不再发送，避免总负责人一早收到两份。
4. 用「预览广告日报」「预览广告异常」看一遍真实内容（实时读 SparkX，只在浏览器显示，不发送）。
5. 保存后，从下一个北京时间 08:30 开始发送。不补发当天已过的时段。

公司日报总负责人和广告总负责人在「通知群设置」里选择。

## 数据口径

- 统计日：生成时洛杉矶时间的前一天，对美洲、欧洲、亚太站点都已结束。日报对比前一天；广告异常用“近 7 日”对比“前 7 日”，都写明具体日期。
- 一次多店查询的金额由 SparkX 统一折算为 USD（SparkX 规则）；JX 不做汇率换算，也不把不同币种相加。
- **没有记录不等于 0**。SparkX 没返回某店当天的数据时，该店不计入合计、列在“当日无花费”或“零数据”里；只有 SparkX 明确返回 0 才显示 0。整站一个店都查不到时，须知里会提示核对 Token 的店铺范围。
- 比率先汇总再相除：ACOS=花费÷销售额，ROAS=销售额÷花费，CVR=订单÷点击，CPC=花费÷点击，TACOS=广告花费÷SparkX 店铺总销售额（取 `asin` 层 `TotalSalesAmount`；拿不到时 TACOS 显示“—”）。分母为 0 显示“—”。
- 近 7–14 天的订单和销售仍会被 Amazon 回补，卡片中已注明；花费和点击当天基本已定。

## 异常判定（只对 USD 金额生效）

| 类别 | 条件 |
| --- | --- |
| 全店零曝光 | SparkX 能查到启用的 campaign，但近两周没有返回任何曝光记录 |
| 零数据店铺（不算异常） | 近两周没有投放记录，也查不到启用的 campaign |
| 异常停摆 | 当前为 enabled，前 7 日花费 ≥ $50，近 7 日无曝光 |
| 高花费零出单 | 近 7 日花费 ≥ $50、点击 ≥ 10、订单明确为 0 |
| 加预算后销售下滑 | 前 7 日花费 ≥ $30，近 7 日花费 ≥ $50 且增长 ≥ 30%，销售下降 ≥ 20%（或此前有销售、现在零出单） |
| ACOS 明显恶化 | 近 7 日花费 ≥ $50，两期都有销售，ACOS 达到前 7 日的 1.5 倍且至少高 15 个百分点 |

每个 campaign 只归入一类，优先级为：停摆 → 零出单/加预算后下滑 → ACOS 恶化。门槛写在 `sparkx_reports.THRESHOLDS`。

## 发送与保护

- 每个北京日期、每个接收人只有一条（持久幂等键）。SparkX 读取失败时每 10 分钟重试，最多 6 次，10:00 后不再生成；已入队的消息 12:00 后过期不发。
- 发送前再次核对：功能仍启用、该发送对象仍勾选、通知群/总负责人/运营没有变化、相关店铺的飞书通知没有被关闭。任何一项变化都跳过并保留记录，不改投、不补发。
- 店铺在运营台关闭飞书通知后，它的 SparkX 数据不会出现在任何卡片里。
- 精简通知模式下这两张卡片照常发送；它们不受“小时广告告警只发群”规则影响。

## 与现有通知的关系

- 领星的 09:00 群日报和每小时广告告警不变。如果某店已经改用 SparkX 观测来源（店铺页「商品推广（SP）观测来源」），该店的领星自动广告告警会被暂停，避免重复。
- 选择“SparkX 直出”作为 08:30 数据源时，领星版公司日报跳过（状态 `SUPERSEDED_BY_SPARKX`）。

## 停用与回滚

- 运营台取消「启用」并保存即可停止，已排队的消息在发送前被跳过。
- 设置文件为 `data/sparkx-report.json`（0600，含店铺对应关系，不含 Token）。代码回滚到旧版本时该文件被忽略，无需数据库或数据卷变更。
