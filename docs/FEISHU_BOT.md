# 飞书机器人（DeepSeek 自由聊天 + SparkX 查询，负责人确认后可修改广告）

## 谁可以用

- 通知群内 @机器人。
- 私聊机器人：总负责人、广告负责人、通知群管理员、店铺目录里的运营，或当前通知群成员（实时核对群成员）。

消息先写入数据库队列，回调里不做任何模型或 SparkX 请求；独立的工作线程逐条回答，回复挂在原消息下。同一人每分钟最多 3 条，排队超过 50 条时群内回复「提问较多」。

## 回答方式

- **自由聊天**：任何话题都可以聊（打招呼、写文案、解释概念……），DeepSeek 直接回答，不访问 SparkX。
- **查数据**：需要数据时，DeepSeek 自己调用 SparkX MCP 的只读工具（工具说明和参数与 SparkX 原样一致），并先阅读对应的官方 Skill（如 `sparkx-query-ads-performance`），用法与 WorkBuddy、Claude 接入 SparkX 时相同。一次回答最多调用 20 次工具（修改广告时见下文）。
- **上下文**：同一段对话记住最近 6 轮（60 分钟内）。私聊按会话；群里按「同一个人」，不会把别人的问题混进来。所以可以直接追问「那前一天呢」「换成 Campx」。
- **正在回答**：机器人开始回答一个问题时，先在这条消息上点一个「OK」表情（私聊和群里 @ 的问题都会；不回答的消息不点，同一个问题只点一次）。点表情需要应用有「获取与发送单聊、群组消息（im:message）」或「发送、删除消息表情回复」权限，当前应用已具备；点不上时照常回答。
- **格式**：回答用飞书卡片展示，Markdown 表格会变成飞书表格；只写结论和数据，不注明数据来源和查询过程。SparkX 返回的数据和官方 Skill 的要求优先于 JX 的对话要求：Skill 要求说明的事项（例如数据是暂定值、结果不全）一句话带过。
- **边界**：DeepSeek 看不到任何凭据。默认没有写操作工具：不会声称已修改广告、预算或出价，需要调整时给出建议由运营操作。

## 修改广告（「广告写入」开启后，所有者要求，2026-11-26）

管理台「SparkX MCP → 广告写入」默认关闭。打开后，总负责人和广告负责人可以让机器人修改广告（出价、预算、状态、否定词、托管组、新建活动等），DeepSeek 按 SparkX 官方写入 Skill 操作；其他人仍只能查询，机器人会说明只有负责人能修改。

1. 负责人提出修改（私聊，或在群里 @机器人）。机器人先读写入 Skill、用只读工具查清对象，列出店铺、对象名称和内部 ID、改动前 → 改动后和影响，最后写「回复「确认执行」后我再修改」。这一轮任何写入调用都会被系统拦截。
2. 同一位负责人在同一段对话里、30 分钟内只回复「确认执行」。系统这时才放行写入工具：DeepSeek 按 Skill 先取得 SparkX 的预览，核对与计划一致后带 confirmToken 提交，执行后读回核对，列出成功和失败的项。预览与计划不一致时停止，重新请负责人确认。
3. 回复里带了别的要求（例如「确认执行，但改成 60」）时不执行，机器人按新要求重新列计划。

一次确认最多 30 次写入调用，回答最多 45 次工具调用、10 分钟。每次写入调用前都重新核对开关，所有者关闭「广告写入」后正在进行的修改立即停下。执行中断（服务重启、超时）时不会自动重来：机器人提示部分修改可能已提交，请先查当前状态。每次写入调用都记在管理台「写入记录」里（不含 confirmToken）。三条定时通知、预览和测试发送始终只读。

DeepSeek 默认开启深度思考（管理台可关闭）：回答更准确，通常 10–60 秒。SparkX 暂时不可用时机器人仍能聊天，并说明暂时查不了数据。

## 开启

1. 管理台「DeepSeek 与机器人」保存 Key，「SparkX MCP」保存 Token 并安装官方 Skills。
2. 飞书开放平台为自建应用开启机器人、订阅 `im.message.receive_v1`（长连接）。
3. `.env` 或运行配置设置 `FEISHU_BOT_ENABLED=true`，启动 `bot` 服务：

```sh
docker compose -p jx-alert -f docker-compose.yml -f docker-compose.runtime.yml --profile bot up -d bot
```
