# 广告分析与飞书通知规则

## 时间与发送对象

所有发送时刻使用北京时间。领星广告事实按各店铺记录的美国太平洋统计日保存，消息中的日报标题继续按北京时间前一日显示。

| 时段 | 系统动作 | 飞书 |
| --- | --- | --- |
| 08:00–18:00 | 每小时刷新广告活动、盘中观测及成熟日报。DeepSeek 复核有证据的异常。 | 每轮在配置的通知群发送一张表，@ 表内店铺的负责人。 |
| 18:00–次日 08:00 | 照常取数和分析，确认后的异常保存为待汇总记录。 | 静默。 |
| 08:00 | 开始采集绩效和经营数据，刷新在投状态，复核昨晚待汇总的广告活动。 | 当天最多一条夜间异常群汇总。实际取数完成后发送，已复核的夜间记录无需再等新一轮 DeepSeek 分析。 |
| 09:00 | 发送上午准备的日报快照。 | 先发全部有依据的店铺绩效与违规，再发经营数据，最后发独立的广告异常页。前页重试时，后页等待。18:00 还未送达的日报页保留记录。 |

- 群卡片和机器人问答中可核查的广告数据用飞书原生表格展示。群卡片列出店铺、活动、异常和关键数据，每张只 @ 卡片内对应店铺的负责人，重复身份合并。没有可验证的人员映射时仍发送群卡片，后台可补充映射。触发点击率告警时，表格同时列出花费、点击、曝光和基准点击率。
- 后台 **通知群设置 → 广告总负责人** 可从当前群成员中选择一人。该人收到即时与夜间广告异常私聊副本。日报、绩效快报和违规观测走原群渠道。如果旧配置包含多人，私聊暂停到重新选择一人为止。
- 发前按当前映射、群权限、店铺通知开关以及活动状态复核。夜间汇总只使用当日 08:00 以后重新核实仍在投放的活动。收件人、群路由或活动权限变化后，旧记录留档。待发内容不会自动迁往新群。飞书回执为实际送达依据。
- 绩效与违规快报沿用既有观测归档口径。它有独立的报告章节。机器人在群 @ 或私聊收到的原会话提问仍可回复。
- 可以私聊问「最近有没有广告异常的广告活动，一次性列举」。默认复核最近七个已结束的美国报表日及可用的当天盘中观测，支持指定 1 到 14 天。遇到空记录、采集失败或报表证据不完整，系统先在调用人和店铺均允许采集的范围内重拉领星报表。有可用的领星 MCP 时，符合条件的失败分区可再查询一次，结果单独归档，归因判断仍以可核验的同口径事实为准。
- 「哪个店铺有异常广告活动」和「拉取所有店铺最新的数据看看有什么广告异常」默认检查当前可见、在运营的店铺。可以直接写店铺名或站点来缩小范围。查询最新数据时单独核对可用的盘中观测；明确查询历史报表日时按指定日期复核。
- DeepSeek 只复核有完整证据的异常候选，系统再次校验证据后在原会话列出结果。每个活动只列一次。重拉后仍缺证据、授权失败或模型无法确认的活动直接略过；没有确认结果时，只回复「没有需列出的异常广告记录」。主动问「最近发过哪些广告告警」时，查询实际已发送的记录。
- 经营日报每张最多汇总五家店铺的已核验表格，保留各店铺的美国统计日、比较日和数据口径。发送前若有店铺失去授权或关闭通知，只移除该店铺的表格。
- 经营 OpenAPI 的原始响应按接口页归档，各页通过同一个采集编号关联。整批完整校验后才提交经营事实和覆盖状态。后续页面写入失败时，保留先前已保存的事实和失败记录。
- 小时巡检启用时，08:00 只由小时调度入口发起采集。任务按开始时刻归入当小时，绩效新鲜度和广告活动状态则以实际校验时刻为准，允许读取本轮刚采到的记录。
- Chat MCP 提交的活动异常沿用证据验证，并使用相同群 @、总负责人、时间段及去重约束。查询和分析仍可执行；提交遇到夜间、冷却或规则配置无效时会返回已复核但未通知。夜间群汇总来自系统每小时的证据复核。

## 哪些数据可以进入判断

1. 按店铺、广告类型和活动比较，金额先核对币种。当前系统的金额告警以已确认的美元事实为准。优先采用同活动七个完整参考日；不足时仅使用同活动精确前一日，且对无转化提高证据门槛。
2. 每一日报分区须完整，归档原始行需能与事实值对上。广告转化使用归因窗口已结束且经过重采的数据。卖家 SP 用七天点击归因；项目给 SB、SD 留十四天。当前自动推送聚焦 SP，SB、SD 仍可按实际可比证据查询。
3. 已确认上线日期的活动先经过观察期，至少七天或该广告类型归因窗口，以较长者为准。无上线日期时，依靠已覆盖的真实成熟历史。盘中判断若缺上线日期也必须有成熟历史依据。
4. 缺记录、源失败、授权异常、跨度不可比、分母为零或数据互相矛盾时，保留源状态并保持飞书静默。成功空记录不会计为真实零。真实零订单须和源销售额、已提供的归因销量一致。
5. 即时活动资格以最新的开启状态和有效店铺授权为准。08:00 汇总发送前复核状态，已暂停或授权失效的活动不发送。昨日历史广告页沿用已成熟的独立报表。

## 异常边界

以下为本项目运营阈值。每项先要求足够样本，再结合绝对影响、相对变化和广告目标。普通变化需要连续两个可比日期出现，重大变化才允许单日进入复核。

| 证据 | 实际判断 |
| --- | --- |
| 点击率 CTR | 点击 ÷ 曝光。比较双方的曝光须达到默认 2,000。绝对与相对降幅足够才进入候选。 |
| 点击花费 CPC | 花费 ÷ 点击。默认至少 30 次点击与 50 美元花费，再检查实质上涨。单纯增加了花费不会触发告警。 |
| 点击转化率 CDR | 归因订单 ÷ 点击。必须用成熟数据。订单减少若主要来自点击量下滑且转化效率未明显恶化，不作为订单异常。 |
| 单件转化花费 CPS | 花费 ÷ 归因销量。分母非零并达到样本要求后比较。 |
| 单均花费 CPA | 花费 ÷ 归因订单。本期与基线需有可比订单样本，才可判断涨幅有无影响。 |
| 广告投入产出 ROAS | 广告归因销售额 ÷ 广告花费。以成熟的同活动证据判断下降。 |
| 总销售广告费占比 TCOAS | 广告花费 ÷ 同口径店铺总销售额。用于店铺经营和主动查询，不把店铺总销售额摊入单个活动。 |
| 有花费但无转化 | 成熟订单与销售额均为零，提供了归因销量时也须为零。当前点击量按该活动历史转化率预计至少 3 单才进入复核。若只用前一日，或推广目标为覆盖、探索，最低预期乘 1.5。 |
| 盘中花费风险 | 仅使用已匹配的当天源超预算事件、已核实的日预算和当天实时花费。默认花费至少为日预算的 2 倍，且高出 2 倍日预算至少 30 美元。反映需复核的花费风险。 |

飞书示例：「今天的花费远超平均日预算」，关键数据为「今天已花 50.08 美元，平均日预算 1.00 美元，比平均日预算多 49.08 美元」。这些是已观测金额，运营可据此核对广告活动。

CTR、CPC、CDR、CPS、CPA、ROAS 的常规相对恶化起点为 30%。CPC 一类风险要区分参考量偏低和当前数据确实显著恶化。转化风险以同一归因口径为准。盘中没有成熟转化结论，也不凭广告金额推断投放浪费、违规、断货或具体搜索词问题。

## DeepSeek 分析指引

系统先确定证据、日期、样本、硬门槛，再将候选与活动目标发给 DeepSeek。模型可以结合搜索覆盖、点击效率、转化和广告目标决定是否值得提醒。每次返回的活动证据编号和异常代码必须来自输入。如果结果不确定、有未知编号或模型调用失败，该批不推送可疑结论。发送的数字由系统根据已通过验证的证据生成。模型没有修改广告、预算、出价或系统路由的权限。

| 活动目标 | 分析指引 |
| --- | --- |
| `balanced` | 同时查看点击质量与成熟转化。 |
| `efficiency` | 优先看效率损失，例如 CPA、CPS 上升或 ROAS 下滑。 |
| `reach` | 优先看覆盖和点击质量，成熟转化须有足够样本才提示。 |
| `discovery` | 对探索投放容忍更宽的早期波动，优先排除小样本误判。 |

### 修改活动分析指引

服务器文件为 `/opt/jx-alert-system/data/ad-review-skills.json`，容器内使用 `/app/data/ad-review-skills.json`。文件可在服务器上修改，下一次分析重新读取。默认无需填写。下面的活动编号仅作示例，实际设置以后台活动编号为准。

```json
{
  "version": 1,
  "defaults": {"objective": "balanced", "min_spend_usd": 60},
  "ad_types": {"sp": {"min_clicks": 40}},
  "campaigns": {
    "5174:sp:141469378857743": {"objective": "discovery", "learning_days": 14, "min_clicks": 60}
  }
}
```

| 配置项 | 默认 | 允许值 |
| --- | ---: | --- |
| `learning_days` | 7 | 整数 7–60 |
| `min_clicks` | 30 | 整数 30–10,000 |
| `min_impressions` | 2,000 | 整数 2,000–10,000,000 |
| `min_spend_usd` | 50 | 50–10,000 |
| `min_relative_change` | 0.30 | 0.30–0.95 |
| `min_expected_orders` | 3 | 3–30 |
| `intraday_budget_multiple` | 2 | 2–10 |
| `intraday_overage_usd` | 30 | 30–10,000 |

目标按活动、类型、全局、默认依次匹配。数值门槛取各层较严者。该文件仅接受版本、限定的字段及数值或枚举，文件上限 64 KiB，最多 300 个活动单独设置。空缺文件使用内置规则。配置格式或字段无效时，系统暂停自动广告异常通知，绩效和经营日报照常。小时告警和日报广告页发送前会重新校验相关活动的有效规则；规则改变的待发广告页留档，其他日报页照常发送。

## 去重与升级

- 即时、夜间汇总和日报广告页按店铺、广告类型、活动和统计日共用去重记录。仍待送达的群消息占用发送名额。飞书确认送达后，以卡片实际展示的活动作为去重依据，同一活动保留 72 小时冷却。群消息失败、过期或活动在发卡前被移除时，下一轮拿到新的有效证据可再次提醒。历史回执继续有效。
- 超过 72 小时、未满七天时，需有更新的源报表日，以及新的风险类型或同指标可证实的显著恶化。恶化要有同比较口径、同币种、至少额外 25% 的不利影响，并达到绝对差，能计算比例时还需再恶化至少 10 个百分点。对应的绝对差为 CTR 0.2 个百分点、CPC 0.25 美元、CDR 2 个百分点、CPA/CPS 5 美元、ROAS 0.5 倍、订单 3 单、无转化花费或盘中超额 30 美元。
- 七天后需要新统计期，且当前证据仍独立满足发报条件，才再次提醒。变更活动名称、调整模型措辞或变更收件人不会打破去重。上一条记录缺少可比数值时，短期内保持静默。
- 采集失败按现有策略重试。过期、拒收和失去权限的消息保留在通知记录。夜间汇总、日报和即时消息各自去重，避免通过补采或刷新重复发送。
- 每轮巡检在后台任务记录中保留有证据候选、去重拦截、模型送审数量与已入队编号。可据此区分没有可靠异常、同一活动处于冷却期及分析失败。
- 配置状态中的最近采集按当前启用的调度模式读取，分别显示最近尝试和最近成功。小时巡检的有记录、空记录和失败以报表分区计数，巡检成功只代表该轮任务已完成。
- 分析规则、卡片或问答共用模块更新后，重启使用这些模块的调度和飞书机器人进程。私聊处理重试耗尽时，只向仍有权读取的原会话说明失败；超出响应时限的原问题留档。
