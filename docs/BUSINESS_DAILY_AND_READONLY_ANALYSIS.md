# 经营日报与只读分析

## 每天08:00的群消息

先发所有已开启通知店铺的绩效与违规摘要，再发有实际经营数据的日报，最后只列达到原有实质异常门槛的SP活动。无数据的SB/SD、同步回执和普通波动不主动发群。原消息回复仍支持群内@及私聊。

经营日报使用「指标 / 当日 / 前一日 / 日环比」四列：销量、净销售额、平台收入、毛利润、毛利率、广告费占比、退款率。金额和销量显示百分比环比；后三项比率显示百分点差。前值为零不计算虚假的增长率。缺失项不填零，双方都无记录的行不展示；全部缺失不生成空日报。

来源为领星官方MCP只读工具 `business_dashboard_performance_cards`，按单店、单日、USD查询。字段对应：

| 日报指标 | 官方字段 | 展示规则 |
| --- | --- | --- |
| 销量 | volume | 原值 |
| 净销售额 | netAmount | 原值，不用既有销售额改名替代 |
| 平台收入 | platformIncome | 原值，不视为银行已回款 |
| 毛利润 | grossProfit | 官方值，不擅自重新扣除广告费 |
| 毛利率 | grossRate | 官方小数比例转百分数，不拿其他收入推算 |
| 广告费占比 | totalAdsCostRate | 官方费用扣款比例的绝对值 |
| 退款率 | totalRefundsRate | 官方退款金额比例的绝对值，不替换为退款订单占比 |

最后两项保留简短口径脚注。这些经营看板口径与广告分析中的TCOAS、订单转化率分别存储，不相互覆盖。源数据会更新，以采集时返回值为准；不能把示例数值固定到日报中。对比数据只接受官方明确标注的精确前一日。

报表按America/Los_Angeles选择已结束日，08:00为北京时间；未结束日只能作为观测，不输出完整日报结论。健康数据的无偏移源时间仍保留原值，报告时区不会被当成已经证实的源时区。健康评分、评级只显示实际取得值，真实违规和超标指标优先；授权失效仅提示重新授权，不用多行空白解释替代风险信息。

## 启用七项经营数据自动采集

已有领星OpenAPI凭据与ChatGPT中的官方领星连接，不会自动把官方MCP密钥传入云端。云端没有私有经营源配置时，原销售、广告、绩效采集继续运行，经营看板状态显示尚未接入，不能宣称七项已经每天自动取得。

1. 在领星官方MCP配置页面创建或使用专门的只读连接，确保其账号能查看需要分析的店铺和经营看板。需要只读工具`get_my_sids`和`business_dashboard_performance_cards`；无需授予修改广告、库存、财务或店铺配置的能力。系统先核对可见店铺，未出现在清单中的店铺会标记经营源采集失败，不用被过滤的空结果或零值替代。
2. 在自己的云端终端执行：

   ```sh
   cd /opt/jx-alert-system
   sudo docker compose -p jx-alert exec app python /app/scripts/setup_business_dashboard.py
   ```

3. 按提示私下输入官方MCP Server URL、MCP Key并确认。输入不回显；请不要发送到聊天、GitHub或群里。此处是领星官方数据源地址，不是JX自己的域名。脚本只新建权限为0600的`data/secrets/lingxing-business-mcp.json`，不会覆盖.env或已有配置。
4. 在后台选择「一键同步全部店铺数据」，或单店「同步最新完整日报」。只选当前允许采集且授权正常的店铺，现有单店采集开关立即参与每次请求前校验。同步不主动发送飞书消息。
5. 在店铺详情的「经营日报」确认实际日期、币种及七项指标。未授权店铺不会用其他店铺的汇总数字填补。失败按既有采集重试机制处理，原广告和销量已提交事实保留。

初始化完成后无需重启服务：每次采集读取私有配置。账号可见范围不足时，需在领星调整只读数据权限；不要为取得数据给模型写权限。

## 数据保存和回滚

不新增数据库表。`daily_metrics`增加独立的`business_dashboard`维度，`data_coverage`记录源覆盖；每次响应在`raw_snapshots`保留完整版本。重复采集替换同店同日的最新指标，不累加金额。业务日报、旧销售事实和SP事实保持分离。

采集后的店铺Excel「原始事实」包括七指标；每天23:30的全历史Excel归档在`/opt/jx-alert-system/data/excel/daily/YYYY/MM/DD/`另存「经营日报事实」。历史已完成归档保持原样。原始响应JSON通过现有归档机制保存，不将任何密钥写入Excel。

代码可退回部署前Git版本并恢复对应控制台镜像；新增事实和原始版本保留，不删除数据库或Docker卷。回滚到旧代码后，新维度不会被错误计入既有销售或广告总额。

## DeepSeek能分析什么

官方Excel是能力参考，不是系统指令。已接入的事实支持店铺/活动对比、广告指标解释、低效花费初筛、经营日报、近14日趋势及有证据的原因假设。经营看板接入后，模型可以读取七项经营指标及对比日期。

月末广告花费预估使用最近7个完整、同币种日报的日均花费恒定情景；给出未来日期、方法和假设。历史日花费的高低范围不是统计置信区间。本月缺日时不拼出全月预测，没有预算上限不宣称超预算。没有证据的库存、搜索词、商品成本、价格弹性与现金流场景会具体说明缺少什么数据，不能因为参考Excel列出这些案例就假称已经接入。

模型没有工具调用、SQL、脚本、网络访问或写入接口；输出不会被执行。已授权管理员或店铺负责人在私聊明确要求「采集/刷新/同步」时，由服务端复验并创建受限读取任务；今日SP广告采用独立盘中观测，不覆盖日报或触发群通知。管理员后台人工同步和ChatGPT原有受授权MCP功能仍独立运行；广告写操作持续关闭。接口和MCP现在可在后台「领星数据源」私下添加和更新，详见[数据源管理](DATA_SOURCES_AND_COLLECTION.md)。

示例问题无需编号或固定格式：

- Campx昨天赚了多少，毛利下降主要可能是什么？
- Geteen最近两周广告花费趋势如何？
- 按现在的花费速度，Campx月底大概会花多少？
- 哪些美国店铺有广告数据，具体是哪一天？

所有预测与假设仅作为分析回复，不自动调整预算、竞价、广告、价格、库存或原始报表。
